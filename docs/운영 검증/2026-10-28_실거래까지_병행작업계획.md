# 실거래까지 병행 작업 계획 (2026-10-28 작성)

> 작성: PC-D / Claude. 대상: 사용자, PC-C·PC-D 작업자(Codex 또는 Claude). 모든 시각은 KST.
> 이 문서는 일정 계획이며 실거래 활성화·실계좌 Secret 연결·주문 승인이 아니다.
> 단계의 내용과 기준은 [5거래일 완료 후 실거래 준비 작업계획](2026-10-23_5거래일_완료후_실거래준비_작업계획.md)(이하 "준비계획")을 따른다. 11/02 전환 절차는 [작업지시서](2026-10-27_PC-C_작업지시_운용중단_5회재시작.md)를 따른다. 내용이 다르면 그 문서와 코드가 우선한다.

## 1. 권장안 (사용자 결정 10/28)

- 새 모의 운용을 **3회가 아니라 5회**로 한다(11/03·11/04·11/05·11/06·11/09 진입, 마지막 보고 11/10 09:40). 조건 확인과 준비계획 2절의 "5회 완료"를 한 운용으로 묶는다. 새 메시지는 3회일 때와 같은 11/03부터 온다.
- 모의 운용이 도는 동안 실거래 준비 중 **AWS·실계좌가 필요 없는 일**을 같이 진행한다.
- 11/02 PC-C 작업은 **승인 목록을 미리 한 번에 받고** 이어서 실행한다. 각 단계의 결과 확인과 중단 조건은 그대로 둔다.
- 운용 도중 판정 조건(코드)을 바꾸면 5회 기록은 처음부터 다시 센다. 조건 변경이 필요해도 11/10까지는 소스만 고치고 배포하지 않는 것을 기본으로 한다.
- 5회가 모두 `NO_TRADE`면 매수·보유·청산 경로는 실제 운영에서 미검증으로 남는다(준비계획 2·4절). 진입을 강제하지 않는다.

## 2. 묶음별 계획

### 묶음 A — 지금~11/02, 동시에 진행 (AWS 접속 불필요)

| 작업 | 담당 | 근거 | 비고 |
|---|---|---|---|
| A1. 실거래 안전 기능 코드·테스트 누락 점검: 계좌 고정, 기존 보유분 보호, 주문 승인 유효기간, 주문/일 손실한도, 중복·동시 실행 차단 | PC-D | 준비계획 5-1 | `live_cli.py`·`live_execution.py`·`live_broker.py` 실제 코드 기준 |
| A2. 가짜 키움 응답 테스트: 부분체결·거부·미체결·취소·응답 유실·재시작 복구·잔고 불일치, 응답 불명 시 자동 재주문 없음 | PC-D | 준비계획 5-2 | 외부 통신 없음 |
| A3. 잠긴 실거래 전용 AWS 템플릿 작성(`LIVE_ORDER_ENABLED=0`, 비상정지 ON, 최소 권한, 모의 원장과 분리) | PC-D | 준비계획 5-3 | 작성만. 배포하지 않는다 |
| A4. 실제 증권사 주문·체결·잔고 검증 계획과 비용·중지·복구 절차 작성 | PC-D | 준비계획 5-4 | 문서 |
| A5. 실계좌 조건 결정: 대상 계좌(번호는 대화에 쓰지 않음), 총투입금, 주문별 상한, 일 손실한도, 주문 방식, 시험 기간, 중지·복구 조건 | 사용자 | 준비계획 6-1 | 결정만. 연결은 하지 않는다 |

A1~A4는 서로 독립이라 같이 진행할 수 있다. 코드 변경에는 집중 테스트와 전체 회귀 테스트를 실행한다(준비계획 5-5). 단, A1~A4에서 모의 운용 경로(`aws_runtime.py`, `engine.py`, `paper_*.py`, batch 템플릿)를 바꾸면 11/02 배포 대상이 달라지므로, 그런 변경은 11/10 이후로 미룬다.

### 묶음 B — 11/02(월), PC-C에서 한 번에 (순서 고정)

1. 09:41 이후 `status` 확인 → `stop`(14:40 전)
2. 새 앱 이미지 빌드·ECR 게시, control Lambda 갱신
3. 새 5회 계획 작성·`paper_batch_checks.py` 오프라인 검사
4. batch 스택 갱신 → `DEPLOYMENT_CHECK`(`DEPLOYMENT_VERIFIED`) → 예약 활성화(ARMED)

앞 단계 결과를 다음 단계 입력으로 쓰므로 동시에 실행할 수 없다. 단계마다 결과를 확인하고, 실패하면 거기서 멈춘다. 2는 `stop` 전에 해도 되지만 PC 접속이 11/02부터 가능하므로 같은 날 진행한다. 11/03 09:45 GATE 전에 4까지 끝나지 않으면 첫 진입일을 미룬 새 계획으로 다시 준비한다.

### 묶음 D — 11/10 09:40 이후, 순서대로 (묶을 수 없음)

1. 5회 완료 판정(준비계획 2·3절, 실제 AWS 기록과 대조). 결과는 `docs/운영 검증/2026-11-10_5거래일_모의운용_검증.md`에 쓴다.

각 단계는 앞 단계의 판정이 근거라 합칠 수 없다. 승인은 같은 날 연달아 받을 수 있다. 1이 `추가 모의 필요` 또는 `전환 불가`면 2로 가지 않는다.
