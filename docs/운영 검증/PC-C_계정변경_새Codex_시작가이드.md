# PC-C 로그인 계정 변경 후 새 Codex 시작 가이드

작성: 2026-10-15 / PC-D / 로컬 기준 커밋 `34ad585`.

이 문서는 **이전 대화를 볼 수 없는 새 Codex가 프로젝트를 이어받기 위한 진입점**이다.
대화 자체를 복원하거나 계정 간 세션 이전을 보장하는 파일은 아니다.
PC-C에서 이후 작업한 내용이 있다면 이 요약보다 최신 공동 인수인계와 실제 파일을 우선 확인한다.

Claude 등 다른 AI로 이어갈 경우에는
[Claude 프로젝트 상세 인수인계](Claude_프로젝트_상세_인수인계.md)의 첫 요청과
파일 접근 가능/불가능 상황별 전달 절차를 함께 사용한다.
전역 지시도 필요한 경우 [글로벌 AGENTS 공유본](글로벌_AGENTS_공유본.md)을 함께 읽힌다.
Claude용 저장소 진입점은 [CLAUDE.md](../../CLAUDE.md)다.

## 1. 사용자가 할 일

1. 이 문서와 관련 변경을 검토한 뒤 PC-D에서 필요한 파일만 commit/push한다.
   이번 문서 작성으로 commit/push가 수행되는 것은 아니다.
2. PC-C의 `C:/Test`에서 먼저 `git status --short`를 확인한다.
   미커밋 변경·충돌이 있으면 pull하지 말고 새 Codex에 파일 목록을 보여주고 정리 방향을 정한다.
   기존 파일을 지우거나 강제 덮어쓰지 않는다.
3. PC-C 작업 트리가 깨끗하면 올바른 브랜치에서 `git pull --ff-only`로 수신한다.
   실패하면 강제로 진행하지 말고 원인을 확인한다.
4. 새 계정으로 로그인한 Codex에서 `C:/Test` 폴더를 열고 아래 첫 요청을 붙여 넣는다.
   해당 환경이 WSL이면 같은 저장소의 실제 마운트 경로를 사용하되 PC alias는 PC-C로 유지한다.

이 문서만 단독으로 전달하면 소스·테스트·기존 기록은 전달되지 않는다.
반드시 전체 저장소와 함께 사용한다. `runtime/`, 로컬 복구 백업과 자격증명은 Git으로 전달하지 않는다.
Codex 로그인 변경을 AWS·키움 계정 변경 요청으로 해석하지 않는다.

## 3. 프로젝트를 이해하기 위한 최소 배경

- 사용자와의 호칭은 사부/제자지만 수익 보장·검증된 투자 실력을 주장하지 않는다.
- 사용자는 AWS 초보자다. 콘솔 작업은 한 단계씩 설명하고 실제 출력으로 성공을 확인한다.
- 증권사 연결은 키움 REST API 기준이다. 토스 연동은 범위 밖이다.
- 주력은 예약형 **종가배팅**: 사전 스캔·후보 축소 후 KRX 15:20 모의진입 또는 NO_TRADE,
  다음 거래일 09:10 기본 모의청산. 15:20은 분석 시작 시간이 아니며 15:30 종가도 아니다.
- 중기 보유 엔진은 별도다. 단타는 단발 모의 기능만 유지하고 AWS 연속 감시는 구현·운영하지 않는다.
- 종가배팅·중기·단타, 모의·실거래, 사용자 실제거래의 자금·포지션·원장·성과를 섞지 않는다.
- 시세·NXT 비대상·촉매·필수 수급이 확인되지 않으면 추정하지 않는다. NO_TRADE는 정상 결과다.
- 실시간 외국인 수급은 판단 요소로 쓰지 않는다. 기관·프로그램 자료도 검증 범위만 사용한다.
- 실거래 예정 자금은 사용자 대화상 **10만원**이다. 코드 기본 예산이나 모의 원장을
  실거래 예산으로 간주하지 말고, 향후 별도 승인 단계에서 확인한다.
- 신규 전용 계좌 사용을 논의했으나 실제 개설·연결 완료를 가정하지 않는다.
  **기존 계좌의 보유종목은 절대 건드리면 안 된다.** 보호 기준선·계좌 확인·프로그램 체결수량 제한을 유지한다.

인증 파일·세션 원본·Secret을 이 문서에 첨부하지 않는다.
