# 실거래 증권사 주문·체결·잔고 검증 계획 (2026-10-28 작성)

> 작성: PC-D / Claude. 대상: 사용자와 PC-C 작업자(Codex 또는 Claude). 모든 시각은 KST.
> [병행 작업 계획](2026-10-28_실거래까지_병행작업계획.md)의 A4 산출물이고, 준비계획 5-4·6-4에 해당한다.
> **이 문서는 계획이며 실주문 승인이 아니다.** 각 단계는 실행 직전에 사용자 승인을 따로 받는다.

## 1. 목적과 범위

가짜 응답 테스트(`tests/test_live_scenarios.py` 등)는 **우리 코드가 정해진 응답에 맞게 동작하는지**만 증명한다. 실제 키움이 그 형식으로 응답하는지는 실계좌로만 확인할 수 있다. 이 계획은 그 차이를 **최소 비용·최소 횟수**로 메운다. 프로그램 내부 가상체결 결과는 증거로 쓰지 않는다.

## 2. 실계좌로만 확인할 수 있는 것

## 3. 단계 (권장안)

전제: A5 실계좌 조건 확정, 잠긴 템플릿 배포, Secret 연결, 기준선 잠금(C3) 완료. 시간은 시가·종가 단일가를 피해 **10:00~14:00**에 한다. 거래소는 KRX만 쓴다.

| 단계 | 내용 | 주문 | 예상 비용 | 확인 항목 |
|---|---|---|---|---|
| **R0** | 읽기만: `ka00001`, `kt00018`, `kt00001`, `ka10074`, `ka10007`, 과거 주문일의 `kt00007` | 없음 | 0원 | V1·V2·V3·V5(형식)·V8·V10 |
| **R1** | 저가 종목 **1주 매수 지정가를 현재가보다 충분히 낮게** 넣는다(체결 안 됨) → 접수 확인 → `live-supervise`로 시간 초과 취소 | 1건+취소 | 0원(미체결) | V4·V5·V6(접수·취소 문구)·V7 |
| **R1b** | 호가 단위에 맞지 않는 가격 등으로 **증권사가 거절할 주문 1건** | 1건(거절) | 0원 | V9·V6(거부 문구). kill switch ON이 정상 |
| **R2** | 저가 종목 **1주를 체결될 지정가로** 매수 → `FILLED` → 프로그램 수량 1 → 계좌 대사 일치 | 1건 | 1주 가격(보유로 남음) | V5·V6(체결 문구), 대사 |
| **R3** | R2의 1주 매도 → `FILLED` → 프로그램 수량 0 → 대사 일치 | 1건 | 호가 차이+수수료+세금(수백 원 수준) | 매도 경로, 기존 보유분 미접촉 |

- 부분체결은 실계좌에서 의도적으로 만들기 어렵다. 가짜 응답 시나리오(부분체결→취소→잔량만 보유)로 대신하고, 실제 발생 시 기록으로 보완한다.
- 각 단계 후 `live-supervise` 결과가 `SUPERVISION_OK`이고 `holding_mismatches`가 비어 있어야 다음 단계로 간다.
- R1b 뒤에는 kill switch가 켜진다. 원인 기록과 수동 대사 후, 해제는 별도 승인으로만 한다.

## 4. 실주문 단계의 잠금 해제 방식

잠긴 템플릿은 `LiveOrderEnabled`가 `"0"`만 허용하므로 R1~R3는 그대로 실행할 수 없다. 권장안: R1~R3 시험 시간에만 `LIVE_ORDER_ENABLED=1`을 허용하는 **시험용 템플릿 변경을 따로 검토·승인**하고, 시험이 끝나면 즉시 `"0"`으로 되돌려 배포한다. 시험 중에도 한도는 주문당 1주·저가 종목으로 운영자가 직접 지킨다. 정기 실거래 예약은 이 단계에 만들지 않는다(준비계획 6-5).

## 5. 중단 조건

다음 중 하나라도 생기면 그 자리에서 멈추고 다음 단계로 가지 않는다.

- 응답 필드가 2절 가정과 다르다(V1~V9).
- `UNCERTAIN`·`CANCEL_SUBMITTING`이 R1b 외 단계에서 생긴다.
- 계좌 대사 불일치, 기존 보유종목 수량 변화.
- 예상하지 못한 체결, 주문 수가 계획보다 많다.
- 키움·AWS 오류가 반복된다.

자동 재주문·재취소는 하지 않는다. 증권사 화면으로 확인한 뒤 원장을 수정하지 않고 상태와 원인을 기록한다.

## 6. 남길 증거 (Git에는 비밀값 없는 요약만)

- 단계·시각·명령·출력 상태 코드(`ACKNOWLEDGED`, `CANCELLED`, `FILLED` 등).
- 응답 **필드 이름과 존재 여부**, 상태 문구 원문(`acpt_tp` 값). 계좌번호·키·주문번호 원문·보유 수량은 적지 않는다.
- 판정: 항목별 `확인 / 불일치 / 미확인`.
- 불일치가 있으면 코드 수정 → 가짜 응답 테스트 추가 → 전체 회귀 → 해당 단계 재시험.

결과는 `docs/운영 검증/<실행일>_실거래_증권사검증결과.md`에 쓴다.

## 7. 비용·횟수 상한 (사용자 승인 대상)

- 실주문 총 4건(R1·R1b·R2·R3) + 취소 1건.
- 1주, 저가 종목만. R2·R3 실제 손실은 호가 차이와 수수료·세금 수준이다.
- 이 상한을 넘기려면 다시 승인받는다.
