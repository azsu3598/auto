# Claude에게 전달하는 프로젝트 상세 인수인계

작성: 2026-10-15 / 작성 환경 PC-D / 저장소 기준 커밋 `34ad585`.

## 0. 이 문서의 목적과 한계

사용자는 기존 Codex와 함께 키움증권 기반 주식 분석·모의매매 프로그램을 만들었다.
PC-C에서 다른 로그인 계정의 Codex 또는 Claude로 작업을 이어가려 한다.
이 문서는 **이전 대화를 읽지 못하는 후속 AI를 위한 배경·안전 규칙·재개 절차**다.

이 문서에는 대화 전체가 아니라 작업에 필요한 주요 합의가 정리되어 있다.
이 문서를 읽었다고 원래 세션·기억·도구 권한·인증이 복원되는 것은 아니다.
Claude가 이전 Codex 대화를 자동으로 읽을 수 있다고 가정하지 않는다.
프로젝트 파일 접근이 가능하면 실제 파일을 읽고, 불가능하면 첨부된 자료만으로 판단한다.
어느 경우에도 확인하지 않은 내용을 실행·검증 완료라고 보고하지 않는다.

이 요약의 날짜보다 최신 작업이 있으면 반드시 공동 인수인계와 실제 파일을 재확인한다.
현재 AWS·키움·PC-C 상태를 PC-D에서 새로 검증한 문서는 아니다.

먼저 Git 상태·브랜치·커밋과 문서 내용을 실제 코드에 대조해줘.

키·토큰·계좌번호·인증 파일·원본 로그를 대화나 Git에 올리지 마.

첫 답변은 다음 네 가지로 정리해줘.
1. 현재 직접 확인한 사실
2. 과거 문서의 기록일 뿐인 내용
3. 남은 작업과 위험
4. 가장 먼저 할 안전한 작업 1개와 필요한 사용자 확인

이 요청은 작업 규칙을 전달하는 것이다. Claude의 실제 실행 환경·권한·자동 문서 탐색은

## 2. 파일 접근 여부에 따라 전달하는 방법

### 같은 PC-C 저장소에 접근할 수 있을 때

- 먼저 `C:/Test`가 맞는지 확인하고 1절의 첫 요청을 보낸다.
- 실제 파일과 Git 상태를 직접 읽게 한다. 파일 첨부만으로 최신 상태를 대신하지 않는다.
- PC-C에 미커밋 변경이 있으면 먼저 보존·검토하고 pull/수정은 멈춘다.
- 작업 트리가 깨끗하고 사용자 요청 범위라면 올바른 브랜치에서 `git pull --ff-only`로 수신한다.
  실패하면 원인을 확인하며 강제 병합·강제 덮어쓰기를 하지 않는다.
- pull 후 필수 세 문서를 다시 읽고 변경 내용을 대조한다.

### 웹 대화 등으로 저장소에 접근할 수 없을 때

우선 아래 문서 8개를 전달한다. 해당 대화 환경의 첨부 가능 형식·개수는 사용자가 확인한다.
개수 제한이 있으면 순서를 나누되 모두 읽기 전 구현을 시작하지 않는다.

1. `AGENTS.md`
2. `PC-C_단독진행_전체인수인계.md`
3. `Codex_세션간_공동_인수인계.md`
4. 이 `Claude_프로젝트_상세_인수인계.md`
5. `PC-C_계정변경_새Codex_시작가이드.md`
6. `stock-automation/README.md`
7. 저장소 루트 `CLAUDE.md`
8. `docs/운영 검증/글로벌_AGENTS_공유본.md`

이 단계에서는 **문서 검토만 가능**하다. 코드 수정이 필요하면 관련 소스·테스트·비식별 오류를
추가로 전달하거나 저장소에 접근 가능한 실행 환경을 사용한다. 실제 코드가 없는 상태에서
전체 구현 검토·회귀 통과·AWS 배포 완료를 주장하지 않는다.

프로젝트 전체를 검토 없이 압축해 올리지 않는다. `.env`, 인증 파일, 키움/AWS/텔레그램 키,
계좌정보, runtime 원본, CloudWatch 원본, 세션 원본과 복구 백업은 제외한다.
대화 원문을 일부 전달할 때도 비밀정보·개인정보를 먼저 제거한다.

## 3. 사용자와 프로젝트의 배경

- 사용자는 기존 AI를 '사부', 자신을 '제자'라고 부른다. 친근하게 설명하되 수익 보장이나
  검증되지 않은 투자 경력·전설적 실력을 주장하지 않는다. 후속 AI가 원래 사부와
  동일한 기억·성능을 가진다고 보장하지 않는다.
- 사용자는 AWS에 익숙하지 않다. 콘솔 작업은 한 단계씩, 실행 위치와 확인할 결과까지 설명한다.
- 사용자는 사용량을 아끼고 싶어 한다. 불필요한 전체 파일 재출력·중복 분석·범위 밖 작업을 피한다.
- PC-D는 `D:/Test`에서 코드·문서·검토를 담당하고, PC-C는 `C:/Test`에서 실제 실행·통합검증을 담당한다.
  코드에는 두 PC의 절대경로를 하드코딩하지 않는다.
- 사용자는 토스와 키움을 사용하지만 프로그램 연동 대상은 **키움 REST API만**이다.
- 실거래 초기 예산으로 **10만원**을 말했으며, 이는 실거래 활성화 승인이나 코드 기본 예산이 아니다.
- 전용 계좌를 논의했지만 개설·연결 완료를 추정하지 않는다. 기존 계좌 보유종목 보호가 필수다.
- 사용자가 직접 commit/push하겠다고 한 경우 이를 존중한다. '이어서 해줘'를 무조건 push 승인으로 해석하지 않는다.

## 4. 전략과 운영 범위

| 전략 | 현재 범위 | 반드시 분리할 것 |
|---|---|---|
| 종가배팅 | 주력. 사전 분석 후 KRX 15:20 모의진입 또는 NO_TRADE, 다음 거래일 09:10 기본 모의청산 | 후보·점수·자금·포지션·손절·원장 |
| 중기 보유 | 수 주~1~2개월 별도 엔진 | 종가배팅·단타의 상태와 성과 |
| 장중 단타 | 요청 시 단발 모의 스캔. AWS 연속 감시·반복 운영은 현재 제외 | 단타 전용 지갑·원장 |
| 배당 적립 | 사용자 개인의 장기 투자·교육 주제 | 프로그램 단기 전략·실거래 원장 |

15:20은 분석 시작 시각이 아니라 최종 판단 기준 시각이다. 15:30 공식 종가와 구분한다.
종가배팅은 기본적으로 NXT 야간 대상 종목을 제외하며 NXT 예약은 꺼둔다.
0~3개 추천 원칙이며, 기준이 안 되면 NO_TRADE다. 요청을 받았다는 이유로 종목을 채우지 않는다.
장중 외국인 수급을 실시간 판단 요인으로 쓰지 않는다. 과거·지연 자료를 현재 수급처럼 쓰지 않는다.
현재 가격·시각·데이터 지연·촉매·NXT·수급·분봉 등 확인하지 못한 것은 미확인으로 표시한다.

기본 종가배팅 설정 `closing-v0.2`는 해당 시장 등락률 **-3% 이하 신규진입 차단**을 포함한다.
이는 현재 로컬 기본 설정 설명이며 미래 운영 환경값이나 새 전략 변경 승인이 아니다.
손절은 `IMMEDIATE`와 `5M_CONFIRMED`를 구분하고, 확인형 손절에도 별도 비상 하드 스톱을 둔다.
갭 하락에서 손절가에 정확히 체결됐다고 가정하지 않는다. 세부 기준은 AGENTS.md와 실제 코드로 확인한다.

## 5. 절대 유지할 안전 경계

1. 실주문·실계좌 Secret 연결·비상정지 해제·실거래 예약 활성화 금지. 별도의 명시적 사용자 승인과 안전 검증이 필요하다.
2. 기존 계좌 종목을 매도하거나 새 전용 계좌가 이미 확인됐다고 가정하지 않는다.
   계좌 확인, 보호 기준선, 프로그램 확인 체결수량, 잔고 대사, 중복 주문 방지를 유지한다.
3. 테스트를 통과시키려고 검증을 삭제하거나 실거래 잠금을 약화하지 않는다.
4. 종가배팅·중기·단타 및 PAPER/LIVE의 자금·포지션·성과를 합치지 않는다.
5. 'AI 원장의 모의체결'과 '증권사 모의주문 제출', '실제 주문'은 서로 다른 상태다.
6. 모의 일주일/5거래일 통과만으로 실거래를 자동으로 켜지 않는다. 기능 안정성과 수익성 검증을 구분한다.
7. 이전 월 2만원 상시 단타 비용 논의를 현재 상시 운영 승인으로 사용하지 않는다.
8. AWS 상태는 조회 없이 단정하지 않는다. 민감한 식별자는 채팅 대신 허용된 로컬 증빙에만 보관한다.

## 6. 현재까지의 진행 상태 — 날짜와 검증 범위 주의

아래는 2026-10-15 PC-D가 보유한 문서 기준이다. 이후 PC-C 작업은 반영되지 않았을 수 있다.

- 코드: 예약형 종가배팅, 중기, 단발 단타, DynamoDB/S3 저장 구조, 알림, PC·모바일 읽기 전용 UI와
  일별 자산 그래프·매매 이유 표시, 실주문 안전 골격이 있다. 구현 파일 존재를 운영 완료로 해석하지 않는다.
- PC-C 2026-10-14 23:57 기록: NAT 네트워크 CREATE_COMPLETE, 재기동 검증 후 EC2 stopped,
  EIP 유지, 모든 예약 DISABLED. 앱 스택/Fargate/S3/DynamoDB의 온라인 통합은 미완료였다.
- 원격 CloudFormation UserData는 초기 설치 제한 60초 버전, 로컬은 600초/최대 2회였다.
  실제 호스트를 복구한 것과 원격 템플릿까지 갱신한 것은 다르다.
- 과거 PC-C 테스트는 Docker 포함 177개 통과, PC-D는 177개 실행 중 175개 통과+2개 skip 기록이다.
  새 환경의 결과가 아니다. 과거 문서 본문의 132/140개를 최신 기준으로 쓰지 않는다.
- 과거 이미지 미해결 고유 69개/High 14개 판정이 남아 있다. 새 스캔 없이 해결됐다고 표시하지 않는다.
- 로컬 요구사항: Python 3.13 이상. Docker opt-in 검사에는 로컬 Docker와 검증 이미지 지정이 필요하다.
- 앱 기본 템플릿은 demo / LIVE_ORDER_ENABLED=0 / 공인 IP 할당 DISABLED다. 안전 기본값을 보존한다.
- AWS 웹 콘솔 로그인과 CLI 인증, 키움 키 발급과 실제 API 읽기 성공을 각각 구분한다.
- Git push가 자동 AWS 배포를 의미한다고 가정하지 않는다. 실제 CI/CD 설정과 승인 절차를 확인한다.

2. 앱 이벤트 유효 시간/재전송과 NAT 실행 창을 맞춘다. 지연·중복·만료·창 초과 테스트를 추가한다.
3. NAT의 실제 HTTPS 준비 확인과 실행 작업 종료를 연동한다. 독립 120분 정지 타이머는 유지한다.
4. 로컬·원격 UserData 차이를 확인하고 변경 세트의 교체·재시작·IAM·비용을 사전 검토한다.
5. 키움 모의 허용 IP, 앱 전용 IAM, 확인된 수수료/세금/휴장일, 이미지 보안을 준비한다.
6. 승인 범위에서 예약 DISABLED 앱 배포와 실제 사설 Fargate 통신·임시 폴더·API·저장·알림을 검증한다.
7. 준비 조건 통과 후에만 핵심 모의 예약 활성화 여부를 별도로 판단하고 5거래일 운영 증빙을 남긴다.

이 순서는 계획이지 이번 문서가 AWS 변경을 새로 허가하는 것은 아니다.
과거 월 $7~10 예상은 비용 상한 보장·신규 자원 승인으로 사용하지 않는다.
유료 자원 추가·권한 확대가 필요하면 대상·위험·비용을 먼저 설명하고 사용자 승인을 받는다.
모든 작업을 한 번에 자동 수행하지 말고 실패 시 안전하게 멈출 단계를 둔다.

## 9. 별도 대화 주제: 배당 적립·차트 공부

이 절은 프로그램 요구사항과 섞지 말아야 할 사용자 대화 배경이다. 새 추천·수익 예측이 아니다.

- 차트 기초부터 교재 형태로 공부하고 싶어 했고 Notion 데스크톱/모바일에서 볼 Markdown 교재를 만들었다.
  최신 경로는 [Sabu 안내](../../Sabu/README.md)와 교재 폴더를 확인한다.
- 배당 적립 대상은 SCHD·JEPQ·ENB였다. 과거 제공 수량 23.32주·11.01주·12.33주는
  당시 스냅샷일 뿐 현재 잔고가 아니다.
- 대화상 적립 규칙: 미국 거래일 기준 SCHD 3,500원+별도 $3.5, JEPQ 4,000원, ENB 3,500원.
  최신 변경이 없는지 사용자에게 확인한 뒤 계산한다.
- 정기 증액은 **2028년부터 매년 2월**, SCHD·JEPQ 각각 하루 500원씩이라는 사용자 정정이 있었다.
  2027년부터로 계산했던 과거 답변을 그대로 이어 쓰지 않는다.
- 다른 개별주 2종목의 적립/매도가 끝날 때는 연도와 무관하게 조기 증액한다.
  종목 1개 종료당 SCHD·JEPQ 각각 하루 500원 증액, 조기 증액도 총 10회 한도에 포함하는 규칙이었다.
  당시 1회 완료·9회 잔여라고 제시됐으나 현재 횟수는 재확인한다.
- 매도 시기는 가격 조건이 있어 미정이다. 사용자가 2027년 6~8월을 예상했어도 확정 일정으로 쓰지 않는다.
- 월 세후 배당에서 TQQQ 투자비 21,000원을 먼저 제외하는 계획과 월평균 배당이 이를 넘길 바람을 말했다.
  연평균과 실제 월별 입금액은 다르고, 배당·환율·세율·수익은 보장되지 않는다.
- 과거 10년/20년 배당 추정값은 이 문서에서 검증하지 않았다. 숫자를 기억으로 복원하지 말고,
  현재 보유량·가격·환율·분배금·세금·증액 시점·재투자 가정을 확인해 다시 계산한다.

## 10. 작업 후 남길 형식

파일 접근과 수정 권한이 있으면 공동 인수인계 10절 최상단에 다음 형식으로 추가한다.
파일을 수정할 수 없다면 같은 형식으로 텍스트를 제공하고 '파일 반영 미완료'라고 명시한다.

```text
날짜/시각 KST — PC-C / Claude / 작업 제목
- 기준 브랜치·커밋:
- 사용자 요청과 허용 범위:
- 직접 확인한 사실 / 과거 기록 / 미확인 상태:
- 변경 파일과 실제 변경:
- 실행한 테스트 명령·개수·통과·실패·skip:
- 실행하지 못한 검증과 이유:
- 남은 위험과 다음 작업 1개:
- 실거래 활성화·실주문·비상정지 상태:
- AWS 변경·비용 발생 여부:
- commit/push 여부:
```

기존 인수인계 기록을 삭제·재작성하지 않는다. 잘못된 기록은 새 기록으로 정정한다.
문서만 수정했다면 전체 프로그램 테스트를 실행한 척하지 말고 링크·형식 검증 범위를 적는다.
코드/전략/안전 변경에는 적절한 새 테스트와 전체 회귀 검증이 필요하다.
테스트를 통과해도 온라인 검증·실거래 승인을 대신하지 않는다.
