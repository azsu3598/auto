# 실거래 잠금 템플릿 운영 안내 (2026-10-28 작성)

> 작성: PC-D / Claude. 대상: 사용자와 PC-C 작업자(Codex 또는 Claude). 모든 시각은 KST.
> [병행 작업 계획](2026-10-28_실거래까지_병행작업계획.md)의 A3 산출물이다. **배포·Secret 연결·실주문 승인이 아니다.**
> 템플릿: `stock-automation/infra/live-locked.yaml`. 내용이 다르면 템플릿·코드·테스트(`tests/test_live_infrastructure.py`)가 우선한다.

## 1. 이 템플릿이 만드는 것

| 리소스 | 이름 | 비고 |
|---|---|---|
| DynamoDB | `stock-automation-live` | 실거래 전용 원장. 모의 `stock-automation-paper`와 분리. 삭제 보호·PITR·Retain |
| ECS 클러스터 | `stock-automation-live` | 서비스·예약 없음. 사람이 `run-task`로 한 번씩 실행 |
| 작업 정의 | `stock-automation-live` | 기본 명령 `--help`(아무것도 하지 않음), 비루트·읽기 전용 루트·권한 제거 |
| 로그 | `/stock-automation/live` | 365일 보관, Retain |
| IAM | `stock-live-execution`, `stock-live-task` | 아래 2절 |

예약(Scheduler)·EventBridge 규칙·Lambda·EC2·ECS 서비스는 **하나도 없다.** 자동으로 실행되는 것이 없다.

## 2. 잠금 방식

- `LiveOrderEnabled`는 허용값이 `"0"` 하나뿐이다. `live-execute`와 `live-supervise`는 `LIVE_ORDER_ENABLED=1`이 아니면 시작하지 않으므로, **이 템플릿으로는 실주문이 불가능하다.** 켜려면 템플릿 자체를 바꾸는 검토와 별도 승인이 필요하다(준비계획 6-5).
- kill switch 기록(`CONTROL#LIVE`)을 만들지 않는다. 코드는 기록이 없으면 **ON**으로 본다.
- 한도 파라미터(주문당 30만 원, 총노출 60만 원, 일 손실 1만 원, 보유 2종목, 같은 종목 하루 매수 1회)는 기본값이 곧 최대값이다. 올리려면 A5 결정 후 템플릿을 고쳐야 한다.
- `KiwoomRealSecretArn` 기본값은 빈 값이다. 비어 있으면 작업에 키움 키가 전혀 들어가지 않고, 실행 역할에 Secret 읽기 권한도 없다. **Secret 연결은 별도 승인된 스택 갱신**으로만 한다.
- 작업 역할: 실거래 테이블에 대해서만 `GetItem`·`PutItem`·`UpdateItem`·`ConditionCheckItem`·`Scan`을 허용한다. `DeleteItem`은 실행 잠금 키(`CONTROL#LIVE_EXECUTION_LOCK`)에만 허용한다. 모의 테이블·모의 S3 버킷은 명시적으로 **거부(Deny)**한다. S3 쓰기, SNS, `iam:PassRole`, `ecs:RunTask`는 없다.

## 3. Secret 형식 (값은 대화·Git에 쓰지 않는다)

Secret 이름은 `stock-automation-live/kiwoom-real`(ARN 접미사 6자 포함)이고, JSON 키는 다음과 같다.

| 키 | 내용 |
|---|---|
| `app_key`, `app_secret` | 키움 실계좌 REST 키 |
| `account_number` | 실계좌 번호. **숫자만** 쓴다. 지문은 이 문자열 그대로 계산하고, 증권사 응답 대조는 숫자만 비교한다 |
| `fingerprint_salt` | 16자 이상 임의 문자열 |
| `approved_fingerprint` | `sha256(fingerprint_salt + "|" + account_number)` 16진수 |

`approved_fingerprint`는 로컬에서 화면에 값이 남지 않게 계산한다(Windows CMD).

```cmd
python -c "import getpass,hashlib;s=getpass.getpass('salt: ');a=getpass.getpass('account: ');print(hashlib.sha256(f'{s}|{a}'.encode()).hexdigest())"
```

## 4. 단계 (각 단계 별도 승인)

1. **잠긴 스택 배포**(Secret 없이): `ImageUri`(digest 고정), `ApprovedAccountAlias`(예: `main`, 계좌번호 아님)만 넣는다. 모의 스택은 건드리지 않는다.
2. **Secret 작성과 연결**: 3절 형식으로 Secret을 만들고 스택을 `KiwoomRealSecretArn`만 바꿔 갱신한다.
3. **계좌 읽기 검증·기준선 잠금**(C3): 아래 명령으로 기존 보유종목을 한 번만 잠근다. kill switch는 ON 상태여야 하고(기본 ON), 증권사 계좌가 설정 계좌 하나와 같아야 한다. 보유 수량·계좌번호는 출력하지 않는다.

   `live-baseline.json`:

   ```json
   {"containerOverrides": [{"name": "stock-automation-live",
     "command": ["live-account-baseline", "--account-alias", "main", "--confirm", "PROTECT_EXISTING_HOLDINGS"]}]}
   ```

   ```cmd
   aws ecs run-task --cluster stock-automation-live --task-definition stock-automation-live --launch-type FARGATE ^
     --network-configuration "awsvpcConfiguration={subnets=[<사설 서브넷>],securityGroups=[<보안그룹>],assignPublicIp=DISABLED}" ^
     --overrides file://live-baseline.json
   ```

   기대 출력: `ACCOUNT_BASELINE_LOCKED`. 이미 잠겨 있으면 덮어쓰지 않고 실패한다(정상).
4. 이후 소액 실주문 검증(준비계획 6-4)과 실거래 활성화(6-5)는 이 템플릿 범위 밖이다.

네트워크는 모의와 같은 고정 IP NAT 경로를 쓰는 사설 서브넷을 기본으로 한다. 키움 실계좌 API가 허용 IP 등록을 요구하는지는 **미확인**이며, 3단계 전에 확인한다.

## 5. 이상 시 대응

| 상황 | 대응 |
|---|---|
| `broker account does not match the approved account` | 키움 토큰 계좌가 Secret 계좌와 다르거나 계좌가 여러 개다. Secret·키 발급 계좌를 확인한다. 우회하지 않는다 |
| `account read is incomplete` | 보유·주문 조회가 20페이지를 넘었다. 원인 확인 전 기준선을 만들지 않는다 |
| `account baseline is already locked` | 정상 보호 동작. 기준선 항목을 지우거나 고치지 않는다 |
| `UNCERTAIN`·`CANCEL_SUBMITTING` 주문 | 자동 재주문·재취소하지 않는다. 증권사 화면으로 수동 대사 후 기록한다 |
| kill switch ON | 원인을 기록하고 해제는 별도 승인으로만 한다 |

테이블·로그·기준선은 삭제하지 않는다. 스택을 지워도 테이블·로그·작업 정의는 Retain으로 남는다.
