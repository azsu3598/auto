# PC-C 검사 보완 적용 순서

## 이번 변경의 범위

2026-10-23 PC-D에서 앞선 점검의 두 검증 공백을 수정했다.

- 기본 인프라 검사는 기존 9개에서 **batch 포함 10개** 템플릿을 검사한다.
- batch의 15개 예약, 기간 참조, 기본 비활성, 독립 정지, 권한/컨테이너 안전 조건을 추가 검사한다.
- 실제 batch 계획의 UTC 밀리초 날짜 형식·존재하는 날짜·시작/종료 순서·승인 날짜 범위·모든 예약 시각 포함 여부를 오프라인 검사한다.
- 네 날짜 매개변수에 템플릿 AllowedPattern을 추가했고, 고정 예시만 검사하던 테스트를 실제 매개변수 검사로 교체했다.
- 신규 테스트 14개를 추가했다. 이 변경은 운영 worker·가상 체결·원장·실주문·현재 AWS 예약을 수정하지 않는다.

**Git pull만으로 AWS에 배포되거나 현재 예약이 갱신되지 않는다.** 기존 일회성 pilot을
다시 만들거나 이미 승인된 계획의 날짜/해시를 바꾸지 않는다.

## 1. Git 수신

Windows CMD에서 실행한다.

```cmd
cd /d C:\Test
git status --short
```

변경이나 충돌이 있으면 먼저 파일을 확인하고 보존한다. clean인 경우에만:

```cmd
git pull --ff-only
```

`AGENTS.md` → `PC-C_단독진행_전체인수인계.md` → `Codex_세션간_공동_인수인계.md`를 읽고,
기존 안전장치 유지·실거래 비활성 상태에서 검증한다고 확인한다.
PC-D의 기존 투자 기록/문서 등 별도 미커밋 변경은 이번 코드 보완 커밋에 섞지 않았다.

## 2. 전체 테스트와 템플릿 검사

기존 `.venv`를 사용한다. 새 AWS 권한이나 Secret은 필요 없다.

```cmd
set PYTHONPATH=C:\Test\stock-automation\src
".venv\Scripts\python.exe" -m unittest discover -s stock-automation\tests -v
".venv\Scripts\python.exe" stock-automation\tools\validate_paper_infrastructure.py
```

기본 validator에 필요한 도구 의존성이 없다면
`stock-automation/infra/requirements-validation.txt`와 기존 검증 환경을 먼저 확인한다.
설치 실패를 검사 성공으로 처리하거나 안전 검사를 끄지 않는다.

기대값: 전체 **375개**, PC-D 결과는 **373통과/선택형 Docker2개 skip/실패0**.
PC-C에서도 Docker 포함 여부·skip 수를 실제 결과로 기록하며 무조건 skip0이라고 쓰지 않는다.
템플릿 검사에는 `TEMPLATES_VALIDATED: 10; BATCH_BOUNDS_AND_PAPER_SAFETY: PASS`가 나온다.

## 3. 실제 batch 계획의 날짜 검사

이 파일이 PC-C에 실제로 존재할 때만 실행한다. 없다고 만들거나 예시 값으로 대체하지 않는다.

```cmd
".venv\Scripts\python.exe" stock-automation\tools\paper_batch_checks.py --plan runtime\paper-batch-plan-20261022-reviewed4.json
```

- 성공: `BATCH_PLAN_AND_SCHEDULE_BOUNDS: PASS; NO_AWS_CALLS; NO_MUTATIONS`.
- 실패: `BATCH_PLAN_VALIDATION_FAILED=...`, 종료코드 1. 계획 내용/계좌/키를 출력하지 않는다.
- 형식은 UTC `YYYY-MM-DDTHH:MM:SS.sssZ`다. 시간대 비교는 KST 승인 날짜를 기준으로 한다.
- PM 범위는 첫 승인 진입일~마지막 진입일이며 GATE 09:45와 마지막 독립 정지 16:20을 포함해야 한다.
- AM 범위는 첫 승인 청산일~마지막 청산일이며 기동 08:55와 마지막 보고 09:40을 포함해야 한다.
- 날짜 검사는 기존 batch 엔진의 모의 전용·5회·달력·연속성 검증을 재사용한다. 원본 파일/원장/예약은 변경하지 않는다.

실패했다고 원격 예약이나 불변 계획을 바로 고치지 않는다. 먼저 오류 코드와 실제 승인 계획을
대조한다. 수정·재배포가 필요하면 현재 예약 상태와 영향을 검토해 별도 진행한다.

## 4. 현재 AWS 상태는 별도 확인

```cmd
".venv\Scripts\python.exe" stock-automation\tools\paper_operations.py status
```

이 명령은 기존 PC-C runtime 연결 자료와 AWS 작업 프로필이 필요하다. 이번 새 날짜 검사는
이 status를 대신하지 않으며, 성공해도 batch가 배포/활성화됐다는 뜻이 아니다.
PC-D는 현재 AWS GATE/서버/예약 상태를 조회하지 않았다.

PC-C는 batch의 실제 계획/스택/예약/arming 증거 유무를 확인해 새 인수인계에 기록한다.
기존 기록은 1회 pilot의 15개 예약 활성화까지만 증명하므로 5회 자동운용으로 확대하지 않는다.
확인하려고 `stop`, arming, 배포, 과거 시험 재생을 실행하지 않는다.

## 검증·안전 경계

PC-D: Python 전체375개(373통과/2skip), 새 테스트14개 포함, Node인증4개,
10개 템플릿 lint/안전 검사, 생성물 일치·구문·공백 검사로 확인한다.
PC-C의 실제 runtime 계획 검사는 이 PC에 파일이 없어 미실행이다.

실거래·비상정지·실계좌 Secret·실주문·현재 AWS 예약 상태는 변경하지 않는다.
기존 과거 FAILED·PASSED·완료 lease·STOP 표식을 삭제하거나 수정하지 않는다.
