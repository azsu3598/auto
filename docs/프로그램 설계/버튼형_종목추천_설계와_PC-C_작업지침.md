# 버튼형 종목 추천 설계와 PC-C 작업 지침

## 최신 승인 범위

초기 설계·샘플 작성 후 사용자가 **배포 이전까지 가능한 개발을 진행하고 테스트 실행은 PC-C에서 하겠다**고 추가 지시했다. 분석 전용 개발 모듈을 별도로 작성하며 운영 자동매매에는 연결하지 않는다. 현재 상태와 PC-C 절차는 [배포 전 개발분과 검증 체크리스트](버튼형_종목추천_PC-C_검증체크리스트.md)가 우선한다. 아래의 설계·샘플 단계 승인 문구를 최신 개발 범위로 오해하지 않는다.

## 설계와 샘플 단계 범위

2026년 10월 23일 PC-D에서 작성했다. 사용자가 원하는 최종 기능은 **기존 프로그램의 모바일 화면에서 버튼을 눌렀을 때만 추천을 받는 기능**이다. 상시 감시나 자동매수 요청이 아니다.

이번 승인은 설계와 오프라인 샘플 UI까지다. 실제 추천 엔진·API·키움 조회·AI 호출·Telegram 전송·AWS 배포·운영 메뉴 연결은 구현하지 않았다. 샘플을 열거나 실행해도 운영 프로그램을 실행하지 않는다. 가상 결과는 추천 학습 CSV, 모의 원장, 실제 투자 내역에 넣지 않는다.

## 샘플 열기

저장소에서 다음 파일을 브라우저로 연다. 별도의 Python·Docker·AWS 로그인이나 Node 설치 없이 화면을 볼 수 있다. 같은 폴더의 CSS·JS도 함께 있어야 한다.

`docs/prototypes/recommendation-preview/dist/index.html`

Windows 탐색기에서 HTML 파일을 더블 클릭하거나 브라우저로 끌어 놓는다. VS Code가 HTML 소스만 열면 탐색기에서 열면 된다. PC-C에서도 저장소 상대 위치는 같다. 현재 AWS 모바일 대시보드에는 이 화면이 나타나지 않는다. 휴대폰 원격 열람용 배포도 하지 않았다.

기본 화면에는 후보가 없다. 시나리오를 선택한 뒤 **종목 추천 · 샘플 실행**을 누르면 약 1초 후 가상 화면이 나타난다.

| 시나리오 | 확인할 동작 |
|---|---|
| 가상 후보 2종목 | 실제 상장종목이 아닌 DEMO_A·DEMO_B, 가상 진입·수량·손절·비상선·목표가 표시 |
| NO_TRADE | 추천 0개, 신규 배정 0원, 가상 현금 100% |
| 자료 만료 | 후보를 숨기고 자료 만료로 차단 |
| 시간 초과 | 후보 없이 실패 이유 표시, 자동 재시도 없음 |
| 조회 실패 | 성공적인 NO_TRADE 분석과 구별되는 실패 상태 |

진행 중 재클릭은 막고 시나리오 선택도 잠근다. 샘플 중단은 이 화면의 지연 표시만 취소하며 운영 매매나 AWS 작업을 중지하지 않는다. 새 실행 시 이전 후보를 즉시 지우고, 취소한 작업의 늦은 결과가 새 결과를 덮지 못하도록 구분한다. 표시 시각은 **시연 완료 시각**이며 실제 시세 기준 시각이 아니다.

## 운영 영향 차단

| 경계 | 이번 구현 |
|---|---|
| 파일 위치 | 운영 앱 밖의 `docs/prototypes/recommendation-preview/` |
| 운영 화면 | `stock-automation/src/stock_automation/dashboard_static/` 수정 없음, 운영 메뉴 링크 추가 없음 |
| 대시보드 API | 기존 `GET /api/dashboard` 변경 없음. 기존 API는 읽기 전용 상태 유지 |
| 배포 경로 | 기존 웹 패키저는 지정된 앱 파일/정적 파일만 포함. Docker도 지정된 앱 소스만 COPY. 샘플 경로는 포함하지 않음 |
| 외부 연결 | 외부 스크립트·폰트·시세·뉴스·AI 호출 없음. CSP `connect-src 'none'`으로 연결 요청 차단 |
| 저장·주문 | 브라우저 저장·원장·S3·DynamoDB·주문·계좌 접근 없음 |
| 반복 실행 | 자동 시작·setInterval·상시 감시·예약 등록 없음. 클릭당 화면 표시용 타이머 하나뿐 |

현재 패키저와 Docker 구성에 기반한 분리다. 향후 누군가 `docs/`까지 배포하도록 패키징을 바꾸거나 샘플을 운영 폴더로 복사하면 이 경계가 깨지므로 금지한다. PC-D는 실제 AWS 자원이나 원격 주문 잠금 상태를 새로 확인한 것이 아니다.

## 실제 기능을 만들 때의 흐름

아래는 후속 설계안이며 구현·배포 완료를 의미하지 않는다.

```text
로그인한 사용자 버튼 클릭
  → 분석 전용 요청 검증과 동시 실행 제한
  → 필요할 때만 제한 시간의 분석 작업 실행
  → 최신 시장 새 스캔과 자료 품질 검사
  → 후보 선별과 위험/손익비 검증
  → 검증된 후보만 AI로 설명
  → 응답 스키마와 숫자/출처 대조
  → 추천 0~3개 또는 NO_TRADE 표시
```

기존 자동매매 worker, 진입 판단, 주문 함수, 자금 지갑, 기존 추천 결과를 호출해 버튼을 대신 구현하지 않는다. 시장 자료 수집 로직을 재사용하더라도 읽기 전용·부작용 없는 경계를 먼저 검사하고 별도 분석 계약으로 감싼다. 종가배팅의 NXT 필터나 15:20/09:10 흐름을 추천 기능에 맞춰 변경하지 않는다. 종가 전략과 추천의 후보·점수·성과를 분리한다.

항상 켜진 서버는 기본안이 아니다. 기존 AWS 기능과 운영비를 검토한 뒤 짧은 작업에 맞는 실행 방식을 고른다. 현재 중계 서버가 꺼진 시각에도 버튼을 쓸 수 있는지, 기동·고정 IP·키움 조회가 어떻게 성립할지는 PC-C에서 별도 검증해야 한다. 버튼이 기존 예약의 서버를 임의로 켜고 끄거나 공유 작업을 취소해서는 안 된다.

### 요청과 결과 계약

요청은 서버가 정한 분석 종류만 허용하고 계좌번호·실거래 옵션·주문 수량·임의 모델명·임의 URL을 받지 않는다. API 키를 브라우저에 두지 않는다. 기존 조회 API를 POST 가능하게 열거나 인증·IAM·CORS를 완화하지 않고, 후속 구현 시 별도 인증된 분석 전용 경로를 설계한다.

결과는 최소한 다음 항목을 갖춰야 한다.

- 요청 ID, 상태, 규칙 버전, 생성 시각, 개별 시세의 실제 기준 시각과 지연 여부
- 거래소 KRX/NXT, 세션, NXT 자격의 확인 여부, 시장 상태와 검증 출처
- 추천 0~3개, 종목별 촉매·지지·수급 근거와 불확실성
- 진입 범위·추격 상한·배정·대략 수량·손절 모드·확인 손절·별도 비상선·목표가
- 제외 사유, 추천 유효기한, 무효화 조건, 자료 품질 실패 이유

기본 상태는 대기, 진행 중, 후보 있음, 정상 NO_TRADE, 자료 만료, 차단, 오류, 취소다. 성공했지만 적격 후보가 없는 NO_TRADE와 자료를 가져오지 못한 오류를 구별한다. 부분 결과나 오래된 캐시를 최신 성공으로 표시하지 않는다. 표시용 후보가 실제 주문이나 모의체결로 변환되지 않도록 별도 타입과 저장 구획을 사용한다.

### 분석 원칙

최신 AGENTS.md를 우선한다. 이전 추천을 출발 종목으로 쓰지 않고 매번 새 시장을 선별한다. 거래대금·당일 기관/프로그램 수급·종가/분봉 구조·검증 촉매·손익비를 함께 평가하며, 외국인 장중 추정 수급은 사용하지 않는다. 테마당 최종 1개, 총 0~3개를 유지한다. NXT는 대화상 추천 허용 범위에 맞춰 검증하되 기존 매매 엔진의 필터는 그대로 둔다.

급등률이나 고배당 표시만으로 추천하지 않는다. 배당형은 단기형과 분리하고 배당 일정·현금흐름·지속성이 확인되지 않으면 제외한다. 손절은 IMMEDIATE 또는 5M_CONFIRMED를 명시하고, 확인 손절에는 별도 비상 하한이 필요하다. AI가 수급·시세·출처를 만들어내거나 규칙 검증에 실패한 후보를 설명만으로 통과시키지 못하게 한다.

AI는 검증된 상위 소수 후보의 설명에만 사용한다. 버튼 횟수·요청당 시간·자료 조회량·AI 사용량 상한은 실제 연동 때 확정하고, 중복 클릭뿐 아니라 서버 측 동시 요청도 막는다. 비용 목표나 추천 성과가 이미 검증됐다고 주장하지 않는다.

## PC-C의 다음 작업

**현재 단계에서는 샘플 확인과 인수인계까지만 한다. 아래 구현 단계는 사용자에게 별도 착수 승인을 받은 뒤 진행한다.**

1. AGENTS.md, PC-C 단독 인수인계, 공동 인수인계의 최신 기록과 실제 코드를 대조한다. 실행 중인 기존 모의운용을 먼저 보호한다.
2. 오프라인 샘플을 열어 모바일 폭·상태 전환·중복 클릭·취소를 확인한다. 샘플을 웹 패키저나 CloudFront에 올리지 않는다.
3. 후속 구현 승인 후 읽기 전용 데이터 이용 조건·API 제한·정확한 시각·분석 가능 시간·서버 기동과 작업 분리를 확정한다.
4. 기존 조회/주문 권한을 넓히지 않고 분석 요청 인증·요청 상한·중복 방지·timeout·오래된 자료 차단부터 테스트한다.
5. 실제 시장 스냅샷을 별도로 저장하고 추천 사후 결과를 평가한다. 가상 시연 데이터는 추천 이벤트 CSV와 성과 기록에 섞지 않는다.
6. 집중 테스트와 전체 앱 회귀를 통과한 뒤 변경 범위와 미검증 사항을 인수인계한다. 배포는 사용자 승인 후 별도 진행한다. 실거래 활성화는 이 기능과 무관하며 별도 승인 대상이다.

## 로컬 검증 명령

Node가 설치된 환경에서 저장소 루트 기준으로 실행한다. 추가 패키지는 필요 없다.

```text
node --check docs/prototypes/recommendation-preview/dist/preview.js
node --test docs/prototypes/recommendation-preview/test-preview.cjs
```

이 검사는 가상 DOM을 사용한 동작·정적 검사다. 실제 브라우저 레이아웃, 모바일 기기, 실제 키움/AI/AWS 연동 성공을 대신하지 않는다. 기존 앱 전체 회귀 명령은 PC-C 단독 인수인계를 따른다.
