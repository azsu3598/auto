# AWS 주식 분석 프로그램 아키텍처

## 목표

AWS에서 한국 거래일에 필요한 시간만 자동 실행되는 종가베팅 중심 시스템을 구축한다.
1차 버전은 종가베팅과 1~2개월 보유 전략을 운영한다. 실시간 단타는 현재 기록만
축적하고 AWS 자동 감시에서는 제외한다.

## 구성

```text
EventBridge Scheduler
        |
        v
ECS Fargate 예약 작업
  ├─ 시장·시세·호가 수집
  ├─ NXT 및 데이터 품질 검증
  ├─ 종가베팅 엔진
  ├─ 단타 기록 적재(자동 감시 비활성)
  ├─ 1~2개월 보유 엔진
  ├─ 위험·수량 계산
  └─ 결과 기록 및 보고서 생성
        |
        ├─ DynamoDB 온디맨드: 추천·체결·성과·규칙 버전
        ├─ S3: 원본 응답·구조화 기록·보고서·백테스트 결과
        ├─ Secrets Manager: 키움·OpenDART·알림 인증정보
        └─ CloudWatch/Telegram: 로그·매매 알림
```

## 종가베팅 작업 흐름

1. 14:50 전체 시장 스캔
2. 15:10 후보와 제외 이유 저장
3. 15:20 최신 KRX 가격 재검증
4. 한 종목 모의 매수 또는 `NO_TRADE` 확정
5. 15:30 이후 당일 데이터와 결과 고정
6. 다음 거래일 09:10 모의 청산 및 성과 계산
7. 전량 청산 후 진입 스냅샷과 이후 실제 5분봉을 학습 사례로 보관
8. 토요일 08:00에 KRX·NXT를 분리해 워크포워드 규칙 비교

## 실시간 단타 — 현재 보류, 향후 연속 구조 설계 완료

현재 대화에서 발생하는 추천과 결과만 CSV에 보존한다. 상시 컨테이너, 웹소켓 및
장중 연속 감시는 활성화하지 않는다. 향후 구현하더라도 별도 기능 플래그와 예산
한도를 적용한다.

실제 장중 단타 기능은 단발 스캔이 아니라 KST 09:00~15:30의 연속 감시가 필요하다.
향후 구현안은 전체 종목을 저빈도로 선별한 뒤 100개 이하 후보를 만들고, 그중
20~50종목만 실시간 정밀 감시하는 EC2 기반 구조다. 현재 Fargate의 가변 공인 IP는
키움 등록 IP 운용에 맞지 않으므로 연속형은 고정 공인 IPv4를 사용한다.

상세 구성, 월 22,000~27,000원 예상비용, 키움 API 제한, 안전 상태기계와 PC-C
구현 순서는 [연속 단타 AWS 운영 설계 및 예상비용](연속_단타_AWS_운영설계_및_예상비용.md)에
정리했다. 문서화만 완료되었으며 EC2 생성·연속 감시 코드·실거래 활성화는 하지 않았다.

## 중기 작업 흐름

장 마감 후 일봉·재무·공시를 갱신하고 주 1회 전체 후보를 재평가한다. 실제 보유
중에는 실적, 공시, 논리 훼손 가격, 목표가 및 최대 보유기간을 매일 점검한다.

## 안전 원칙

- 데이터 기준시각과 지연 여부를 모든 판단에 저장
- 동일 작업의 중복 추천·체결 방지를 위한 멱등 키 사용
- API 실패나 가격 불일치 시 거래하지 않음
- 실제 주문 모듈은 별도 승인 전까지 포함하지 않음
- 종가베팅·단타·중기·사용자 실제투자의 자금과 손익을 분리

## 비용 원칙

- 24시간 ECS 서비스와 고정 RDS 인스턴스를 초기 버전에서 사용하지 않음
- EventBridge가 정해진 시간에 Fargate 작업을 실행하고 완료 후 즉시 종료
- 종가베팅은 14:50~15:30 및 다음 거래일 09:05~09:15에만 실행
- 중기 분석은 장 마감 후 일 1회, 전체 재평가는 주 1회 실행
- DynamoDB 온디맨드와 S3를 사용해 유휴 시간의 고정비 최소화
- CloudWatch 로그 보존기간과 S3 수명주기를 설정해 누적 저장비 통제
- 향후 연속 단타를 승인하면 `t3.medium`·고정 공인 IPv4·`gp3 20GB` 기준 월
  22,000~27,000원, 안전 예산 상한 30,000원을 별도 기준으로 사용
- 연속 EC2와 기존 Fargate가 같은 전략을 동시에 실행하지 않도록 실행 주체를 단일화

### 체결 알림

모의매수, 부분익절, 전량매도 및 손절 이벤트가 DynamoDB에 처음 기록된 뒤 무료
Telegram Bot API로 알림을 발행한다. 멱등 조건에 걸린 재실행은 같은 모의체결을
다시 만들지 않는다. 실주문이
추후 승인되면 `주문 접수`, `부분 체결`, `전량 체결`, `거부·취소`를 서로 다른
이벤트로 구분하고, 브로커 체결 확인 전에는 매수·매도가 완료됐다고 알리지 않는다.
봇 토큰과 `chat_id`는 Secrets Manager에서 실행 시점에 읽으며 로그나 결과 파일에
남기지 않는다. 현재 알림은 모두 `모의매매`로 표시한다. 카카오톡 `나에게 보내기`도
선택형으로 지원하지만 기본 알림은 별도 심사와 OAuth 갱신이 없는 텔레그램이다.
기존 SNS 이메일 구독 역시 선택형 대체 채널로 유지한다.

## 기록 기반 자기 보완

종료 거래마다 진입 당시 전체 스냅샷과 실제 진행된 5분봉을 S3의 세션별
`replay-cases/`에 저장한다. 주간 작업은 과거 70%를 훈련, 최신 30%를 검증으로
분리하고 기존 챔피언과 도전 규칙을 동일한 수수료·세금 조건으로 재생한다.

자동 승격은 최소 사례 수, 최소 검증 거래 수, 양의 검증 순손익, 성과 개선 및
최대낙폭 제한을 모두 통과한 경우에만 허용한다. 자동 조정 범위는 최소 차트 점수,
종가 강도, 거래량 팽창률, 과열 상승률 및 5일선 이격도뿐이다. 자금 한도, 손실
한도, 주문 권한은 학습기가 바꿀 수 없으며 승격 규칙도 `PAPER_ONLY`로만 작동한다.

## 현재 구현 상태

프로그램 본체는 `stock-automation/`에 구현을 시작했다. 현재 다음 기능이 코드와
단위 테스트로 존재한다.

- 키움 REST API `ka10099`, `ka10032`, `ka10007`, `ka10081`, `ka10080`,
  `ka20001`, `ka90001`, `ka90002`를 이용한 종목·시세·호가·일봉·5분봉·시장지수와
  테마 강도 수집
- KRX 15:20과 별도 NXT 19:55 세션의 후보 평가 및 모의체결
- 거래대금, 거래량 증가, 종가 강도, 5분 20이평, 일봉, 촉매, 호가 기반 점수화
- 차트 중심 지표인 5·20·60·120일선, RSI(14), ATR(14), 세션 VWAP, 5분봉 거래량
  팽창, 최근 1시간 수익률, 고점·저점 상승, 돌파 후 지지 및 상단 저항 공간 계산
- NXT 제외, 테마당 한 종목, 데이터 지연 차단, 일일 손실 한도와 수량 계산
- 다음 거래일 09:05 위험 점검과 09:10 모의청산
- 전량 청산 후 키움 과거 5분봉을 이용한 재생 사례 자동 적재
- 거래비용·갭·부분익절·확정 손절을 반영한 5분봉 백테스트
- 훈련/검증 분리와 안전 게이트를 적용한 주간 모의규칙 자동 개선
- 별도 입력·결정 ID·원장을 사용하는 20~40거래일 일봉 중심 중기 엔진
- 키움 `ka10001` 재무·밸류 지표와 OpenDART 자동 공시 위험 확인을 결합한 실패 폐쇄 필터
- JSONL·CSV·Markdown 로컬 기록과 S3·DynamoDB AWS 기록
- KRX·NXT·중기 전략별 독립 지갑과 수수료·세금 반영 누적 가용현금/순실현손익
- 매수·매도·손절·전략 승격 텔레그램 알림과 선택형 카카오 어댑터
- 10개 EventBridge Scheduler 작업과 ECS Fargate용 CloudFormation 초안

실제 주문 호출 코드는 존재하지 않는다. 공시 위험 자동 수집과 중기 엔진의 AWS
예약·보유 포지션 재평가는 구현됐다. 현재 남은 주요 작업은 뉴스 촉매 자동 수집, 키움 모의투자 키를
이용한 통합 테스트 및 CloudFormation 실제 배포 검증이다. 실제 주문은 모의운영
성과 검증과 별도 사용자 승인을 거친 이후에만 체결 상태기계·비상정지 장치와 함께
추가한다.

실주문 사전 안전 모듈은 기본 비활성화, 주문별 사용자 승인 해시, 승인 만료,
최신 시세, 주문금액·총노출·일손실·보유종목 한도, 중복방지 및 비상정지를 검사한다.
이 모듈은 주문 전송 어댑터와 연결되어 있지 않으므로 현재 배포본은 여전히
모의매매만 수행한다.
