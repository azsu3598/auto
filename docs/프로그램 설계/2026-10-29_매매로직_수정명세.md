## 1. [높음] 손절·목표가가 사실상 고정 비율이다

### 현재 동작

- `risk.py:49` — `soft_stop = round_tick(min(support_price, entry × 0.975))`
- `risk.py:50` — `emergency_stop = round_tick(min(soft_stop × 0.985, entry × 0.955))`
- `risk.py:68-69` — 목표가 = 진입가 + 손절폭 × 1.5 / × 2.5
- 수량은 비상손절 기준 손실이 `max_daily_loss`(10,000원) 이하가 되도록 계산한다(`risk.py:61`). 이 원칙은 유지한다.
- 키움 어댑터는 지지선을 `max(5일선, 5분 20이평, VWAP, 장중 돌파선, 최근 5일 저가)` 가운데 현재가 아래 값으로 정한다(`providers/kiwoom.py:596-641`).
- 종가배팅 하드 필터는 현재가가 VWAP과 5분 20이평 위에 있어야 통과한다(`engine.py:176`, `engine.py:184`). 따라서 지지선은 늘 현재가 바로 밑에 있고, `min()`은 거의 항상 `entry × 0.975`를 고른다.

PC-D에서 실제 계산한 결과(현금 600,000원, 배분 40%, 최대 손실 10,000원):

| 진입가 | 지지선 | 손절 | 비상손절 | 1차 목표 | 2차 목표 | 수량 |
|---|---|---|---|---|---|---|
| 10,000 | 9,950 | -2.50% | -4.50% | +3.80% | +6.20% | 22 |
| 30,000 | 29,800 | -2.50% | -4.50% | +3.67% | +6.33% | 7 |
| 4,980 | 4,900 | -2.51% | -4.52% | +3.82% | +6.22% | 44 |
| 10,000 | 9,000 | -10.00% | -11.40% | +15.00% | +25.00% | 8 |

### 문제

1. 손절이 차트 구조나 종목 변동성과 무관하게 -2.5% / -4.5%로 고정된다. 일봉 ATR14가 8%인 종목은 다음 날 시초 흔들림만으로 비상손절에 걸리고, ATR이 2%인 종목은 손절이 지나치게 넓다.
2. `Quote.atr14`는 계산·보고만 하고(`indicators.py:133`, `reporting.py:148`) 손절에는 쓰지 않는다. 중기 전략은 이미 ATR 기반 손절을 쓴다(`medium_term.py:386-389`).
3. 손절 폭 상한이 없다. 지지선이 멀면(표 마지막 줄) 손절 -10%, 2차 목표 +25%처럼 다음 날 09:10까지 도달하기 어려운 계획이 나온다. AGENTS.md 5절의 "손절이 충분히 가까워 손익비가 유리할 것" 조건을 코드가 확인하지 않는다.
4. `INVALID_SUPPORT` 하드 필터(`engine.py:178`)는 사실상 걸리지 않는다.

### 수정 방향

`build_position_plan`에 손절 방식 인자를 추가하고, 종가배팅만 새 방식을 쓴다.

```text
입력: entry, support, atr14 (일봉 ATR14, 원 단위)
soft_distance  = max(entry - support, SOFT_ATR_MULT × atr14)
                 → 하한 MIN_STOP_PCT × entry
soft_distance  > MAX_STOP_PCT × entry 이면 → 계획 없음 (NO_TRADE, 사유 STOP_TOO_WIDE)
soft_stop      = 호가단위로 내림(entry - soft_distance)
emergency_stop = 호가단위로 내림(soft_stop - HARD_ATR_MULT × atr14)
                 → entry 대비 MAX_HARD_STOP_PCT 보다 멀면 NO_TRADE (STOP_TOO_WIDE)
수량           = 지금처럼 min(배분 한도, max_loss // (entry - emergency_stop))
목표가         = 지금처럼 entry + soft_distance × 1.5 / × 2.5
```

| 상수 | 제안값 | 의미 |
|---|---|---|
| `SOFT_ATR_MULT` | 0.5 | 손절폭 최소 = ATR의 절반 |
| `HARD_ATR_MULT` | 0.5 | 비상손절 = 손절 아래로 ATR 절반 더 |
| `MIN_STOP_PCT` | 1.5% | 손절폭 하한 |
| `MAX_STOP_PCT` | 5.0% | 손절폭 상한, 넘으면 진입 안 함 |
| `MAX_HARD_STOP_PCT` | 7.0% | 비상손절 상한, 넘으면 진입 안 함 |

- 상수는 `StrategyConfig` 필드로 둔다. `learning.py`의 자동 조정 대상(5개 항목)에는 **넣지 않는다**.
- 제안값은 출발점이다. 5회 운용 기록과 `replay-cases` 백테스트 결과를 보고 사용자가 확정한다.
- 호가단위 처리: 현재 `_tick_round`는 반올림이라 손절가가 위로 올라갈 수 있다. 손절·비상손절은 **내림**, 목표가는 반올림을 쓴다.

### 1-1. ATR이 없을 때

`Quote.atr14`가 `None`이거나 0 이하이면 종가배팅은 NO_TRADE(사유 `ATR_UNAVAILABLE`)로 처리한다. `engine.rejection_reason`에 하드 필터로 추가하고(DART 검사 다음), `tools/rejection_report.py`에 한국어 라벨을 추가한다. 키움 경로는 항상 ATR을 계산하므로 운영 영향은 없다. 다만 `tests/test_engine.py` 등의 기존 fixture에는 `atr14`가 없으므로 값을 추가해야 한다(기대값 변경 내역을 인수인계에 적는다).

### 1-2. NO_TRADE 사유

`engine.py:83`은 `plan is None`이면 모두 `POSITION_SIZE_ZERO`로 기록한다. 손절 폭 초과는 원인이 다르므로 `STOP_TOO_WIDE`로 구분해 기록한다(예: `build_position_plan`이 거절 사유를 돌려주게 하거나, 별도 검사 함수를 먼저 호출).

### 1-3. 필수 테스트

- ATR이 작은 종목: 손절폭 = `MIN_STOP_PCT`.
- ATR이 큰 종목: 손절폭 = `0.5 × ATR`, 수량이 줄어 비상손절 손실 ≤ 10,000원.
- 손절폭 > 5% 또는 비상손절 > 7%: NO_TRADE `STOP_TOO_WIDE`.
- `atr14=None`: NO_TRADE `ATR_UNAVAILABLE`.
- 호가단위 경계(예: 진입가 2,000원·5,000원·20,000원·50,000원 부근)에서 손절가가 의도보다 위로 올라가지 않는다.
- 모든 경우에 `risk_amount ≤ max_daily_loss`.

### 1-4. 단타 영향 차단

`day_trade.py:183`도 같은 함수를 호출한다. 새 인자의 기본값은 **현재 동작과 완전히 같아야** 한다. `tests/test_day_trade.py`의 기존 기대값이 하나도 바뀌지 않는 것을 확인한다. 단타 손절을 바꾸려면 별도 작업으로 한다.

### 1-5. 학습 챔피언 파일 주의

`learning.config_from_champion`(`learning.py:220-223`)은 저장된 챔피언 파일의 `rule_version`으로 설정 버전을 덮어쓴다. v0.3 기준으로 승격된 `config/rules/KRX_1520.json`이 있으면 v0.4 로직에 옛 버전 이름이 붙는다. 기준 버전이 다른 챔피언은 로드하지 않도록 막는다(예: 챔피언 payload에 `base_rule_version`을 저장하고 불일치 시 거부). 현재 S3에 챔피언 파일이 있는지는 PC-C에서 확인한다(승격 조건이 최소 40건이라 없을 가능성이 높지만 확인하지 않았다).

## 2. [중간] 검증되지 않은 테마 강도가 점수에 최대 6점 들어간다

### 현재 동작

- `engine.py:254` — `score += min(6.0, max(0.0, q.catalyst_score) × 6.0)`. `catalyst_verified` 여부를 보지 않는다.
- 키움 테마 강도(`ka90001`·`ka90002`)는 `Catalyst(..., verified=False)`로 만들어진다(`providers/kiwoom.py:249-256`). 그래도 `catalyst_score`는 그대로 들어간다.
- README는 "키움 테마 강도는 맥락으로만 사용하며 검증 촉매로 인정하지 않는다"고 적고 있다.

### 문제

통과선이 60점이므로, 검증 안 된 테마 상승만으로 6점을 받아 경계선 종목이 통과할 수 있다.

### 수정

```python
catalyst_confirmed = q.catalyst_verified and bool(q.catalyst.strip())
if catalyst_confirmed:
    score += min(6.0, max(0.0, q.catalyst_score) * 6.0)
    score += 4.0
```

테마 이름(`q.theme`)은 지금처럼 테마 분산(`_diversify`)에 계속 쓴다.

### 테스트

- 같은 종목에 `catalyst_verified=False`, `catalyst_score=1.0`이면 점수가 `catalyst_score=0.0`일 때와 같다.
- `catalyst_verified=True`이면 지금과 같은 점수를 받는다.

## 6. 수정 대상이 아닌 참고 사항

- **15:20 체결가와 동시호가.** KRX 정규장 접속매매는 15:20에 끝나고 15:20~15:30은 종가 단일가 매매다. 실제 주문은 15:30 종가로 체결되므로, 15:20 매도호가로 기록하는 모의 체결가(AGENTS.md 17절 사용자 규칙)와 차이가 생긴다. 지금 바꿀 대상은 아니다. 실거래 전환을 검토할 때 모의 기록에 15:30 공식 종가를 함께 남겨 차이를 측정하는 기능을 별도로 제안한다.
- **09:10 청산 구조에서 5분봉 확인 손절.** `exit_engine.py:30-34`는 5분봉 하나가 손절가 아래에서 닫히고 다음 봉이 회복하지 못해야 손절한다. 09:00 이후 두 봉이 닫히는 시각이 09:10 예약 청산과 같으므로, 실제로는 09:05 비상손절만 작동한다. 수량을 비상손절 기준으로 계산하므로 위험 한도와는 맞다. 1번 수정 후에도 이 구조는 그대로다.

## 7. 작업 순서 요약

1. (언제든) 5번 README 정정.
2. (11/10 5회 운용 종료 후) 사용자에게 1·3번 제안값 확정을 받는다.
3. 1번 + 2번 + 4번 → `closing-v0.4`, 테스트 추가, 전체 회귀.
4. 3번 → `day-trade-v0.3`, 테스트 추가, 전체 회귀.
