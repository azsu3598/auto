# 주식 추천 프로그램 시행착오 규칙 명세

## 제작 책임과 최종 목표

이 기록을 바탕으로 프로그램을 설계하고 구현하는 주체는 **Codex**다.
문서 작성으로 작업을 끝내거나 다른 개발자에게 구현을 전제로 넘기지 않는다.
Codex는 누적된 추천 이벤트와 시행착오를 규칙으로 변환하고, 프로그램 코드,
테스트, 백테스트 및 결과 검증까지 직접 수행한다.

초기 프로그램의 기본 동작은 **추천 및 모의투자**다. 실제 주문 기능은 사용자가
별도로 요청하고 계좌·주문 권한과 안전장치를 명시적으로 승인하기 전에는 구현하거나
활성화하지 않는다.

## 제작 대상

1. 키움 REST API 등을 이용한 KRX 시세·분봉·호가·거래대금 수집기
2. NXT 대상 제외와 데이터 최신성 검증 모듈
3. 시장 상태, 테마 분산, 기술 구조 및 호가를 평가하는 후보 검색기
4. `IMMEDIATE`와 `5M_CONFIRMED`를 구분하는 손절·재진입 판단 엔진
5. 총손실 한도에 맞춘 수량·현금 비중 계산기
6. 추천, 제외, `NO_TRADE`, 정정 및 사후 결과를 저장하는 이벤트 기록기
7. MFE·MAE와 시간대별 수익률을 이용한 백테스트·규칙 비교 도구
8. 사용자 실제 투자와 AI 모의투자를 분리한 대시보드 및 보고서

프로그램은 수익 종목을 많이 찾는 것보다 잘못된 진입, 늦은 추격, 성급한 손절을
줄이는 것을 우선 목표로 한다.

## 전략 우선순위

프로그램의 기본 전략과 최우선 개발 대상은 **종가베팅**이다. 1차 AWS 프로그램은
종가베팅과 1~2개월 보유 전략만 실행한다. 장중 단타는 현재 대화에서 발생한 추천과
결과를 데이터로 계속 저장하되 자동 감시·실행 엔진은 당분간 만들거나 켜지 않는다.

### 1. 종가베팅 엔진

- 14:50 KST부터 전체 KRX 정규장 종목을 새로 검색
- NXT 대상 종목 제외
- 15:10 전후 후보 압축 및 위험 재검증
- 15:20 KST 최신 확인가로 최종 모의 매수 또는 `NO_TRADE` 확정
- 다음 거래일 09:10 KST 기본 청산, 사전 손절·분할익절 규칙 적용
- 추천과 체결 결과를 종가베팅 전용 원장에 저장

### 2. 실시간 단타 기록 — 현재 비활성

- 현재 대화에서 수행한 단타 추천·제외·손절·정정 결과만 이벤트 CSV에 저장
- 단타 추천과 실제·모의투자 원장은 계속 분리
- AWS에서 장중 상시 시세·호가 수집이나 포지션 감시는 실행하지 않음
- 사용자가 다시 질문하기 전에는 가격을 연속 감시한 것으로 간주하지 않음
- 향후 충분한 데이터와 비용 필요성이 확인될 때 선택 기능으로 구현

### 3. 1~2개월 보유 엔진

종가베팅과 별도의 후보군·점수·자금 원장을 사용한다. 목표 보유기간은 약 20~40
거래일이며 단기 등락보다 다음 항목을 중점 평가한다.

- 매출·영업이익·현금흐름과 실적 추세
- 부채, 이자 부담, 유상증자·전환사채 등 희석 위험
- PER·PBR과 업종 내 상대 가치
- 20·60·120일선, 중기 지지와 최대 허용 낙폭
- 향후 1~2개월 안의 실적·정책·산업 촉매
- 배당의 지속 가능성과 하락 시 보유 완충 역할

단타 손절선을 중기 종목에 적용하지 않고, 중기 보유 논리가 훼손되는 가격·실적·
공시 조건을 별도로 정의한다. 종가베팅 손실을 중기 계좌의 물타기로 복구하지 않는다.

## 실행 환경

프로그램은 로컬 PC가 아니라 **AWS에서 상시 운영**하는 것을 전제로 한다. AWS 계정과
비용 범위가 확정되기 전의 기본 설계는 다음과 같다.

- 컨테이너 실행: 필요 시간에만 시작되는 Amazon ECS Fargate 예약 작업
- 정시 실행: Amazon EventBridge Scheduler
- 거래·추천 데이터: 초기에는 Amazon DynamoDB 온디맨드 또는 S3 구조화 파일
- 원본 시세·분봉 및 보고서 보관: Amazon S3
- API 키와 계정 정보: AWS Secrets Manager
- 실행 로그·경보: Amazon CloudWatch 및 SNS
- 장애 시 중복 실행 방지와 재처리가 가능한 작업 ID 사용

한국 시간대와 거래일 캘린더를 명시적으로 적용하고, 15:20 작업이 실패하면 임의
가격으로 체결하지 않고 `PENDING` 또는 `NO_TRADE`로 안전하게 종료한다.

비용 절감을 위해 24시간 또는 장중 상시 실행되는 컨테이너와 고정 RDS 인스턴스는
초기 버전에서 사용하지 않는다. 종가베팅, 다음 날 청산, 장 마감 후 중기 분석 시간에만
예약 작업을 실행하고 작업 완료 즉시 종료한다.

## 목적

추천 결과뿐 아니라 추천 당시 판단과 이후 실패 원인을 구조화하여 향후
검색·백테스트·자동화 프로그램에 사용한다. 수익 종목만 남기지 않고
`NO_TRADE`, 오손절, 미체결, 사용자 거절도 동일하게 기록한다.

## 2026-09-29 핵심 사례

### 한켐: 성급한 손절과 휩쏘

- 11:40 추천 확인가 11,900원, 기존 손절 11,500원
- 13:10 확인가 11,390원에서 즉시 매도를 제시
- 13:12 한 분 동안 11,390원에서 11,820원까지 급반등
- 사용자 매도는 확인됐지만 매도가와 수량은 미확인
- 분류: `PREMATURE_STOP`, `WHIPSAW_AFTER_EXIT`

개선 규칙: 소형주이고 새로운 악재가 없다면 단일 체결가가 아니라
`5분봉 종가 이탈 + 다음 봉 회복 실패`로 소프트 스톱을 확인한다. 단,
별도의 비상 하드 스톱을 사전에 정한다.

### 빅텍: 급등 후 테마 약화

- 11:40 확인가 3,160원, 손절 3,040원
- 13:10 확인가 3,005원으로 손절선 이탈
- 방산 대형주가 동반 약세였는데 오전 상승률만 과대평가
- 분류: `LATE_ENTRY`, `THEME_DIVERGENCE`, `STOP_BREACH`

개선 규칙: 테마주는 대표주와 동행하지 않으면 제외한다. 당일 고점 대비
낙폭, 5분봉 20기간선의 위치와 기울기, 돌파 후 지지 여부를 확인한다.

### 고영: 매도벽 미확인

- 가격·분봉 조건만으로 추천했으나 사용자가 강한 매도벽을 확인
- 실시간 호가 데이터를 검증하지 못한 상태에서 공급 부담을 누락
- 분류: `ORDERBOOK_UNKNOWN`, `USER_REJECTED`

개선 규칙: 호가 데이터가 없으면 `매도벽 미확인`으로 표시한다. 신뢰할
수 있는 호가가 확보되면 매도잔량 집중, 매수잔량 지지, 돌파 반복 실패를
진입 필터로 사용한다.

## 프로그램 필수 데이터

- 추천 ID, 규칙 버전, 전략, 분석·확인 시각
- 종목·코드·NXT 여부와 시장 상태
- 현재가, 일중 고저, 거래량·거래대금, 주요 분봉 지표
- 진입 범위, 손절 방식, 손절선, 비상 하드 스톱, 목표가
- 추천·제외·`NO_TRADE` 결정과 이유 코드
- 5·15·30·60분, 종가, 다음 거래일 가격
- 최대 유리 변동(MFE), 최대 불리 변동(MAE)
- 실제·모의 체결 여부, 가격, 수량, 비용 및 손익
- 사후 결과 코드와 규칙 수정 내용

## 데이터 원칙

실제 체결과 모의 체결을 분리한다. 사용자가 제공하지 않은 체결가·수량은
비워둔다. 이후 확인 가격을 과거 손절가나 목표가에 소급 체결하지 않는다.
규칙을 변경할 때 기존 행을 고치지 말고 새 규칙 버전과 정정 이벤트를
추가하여 당시 판단을 보존한다.
