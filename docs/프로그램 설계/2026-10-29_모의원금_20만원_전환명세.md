# 2026-10-29 모의 원금 20만 원 전환 명세

## 결정

사용자가 2026-10-29에 실거래 원금을 20만 원으로 정했다. 모의도 **다음 운용(11/03~11/10 5거래일)부터
20만 원**으로 한다. 모의와 실거래의 원금을 같게 해서, 모의 성적을 실거래에 그대로 옮길 수 있게 하려는 것이다.

손실 한도와 배분은 지금(60만 원 기준)의 1/3로 맞춘다. 배분 비율(%)은 그대로 두므로 금액만 줄어든다.

## 현재 구조 (main 기준 확인)

- **시작 금액:** 환경변수 `STARTING_CASH`, `MEDIUM_STARTING_CASH`, `DAY_TRADE_STARTING_CASH`이다.
  - 기본값은 `aws_runtime.py`에서 600000이다.
  - CloudFormation 파라미터 `StartingCash`, `MediumStartingCash`, `DayTradeStartingCash`도 기본값이 600000이다. 이 파라미터는 `infra/cloudformation.yaml`, `paper-five-session-batch.yaml`, `paper-one-session-pilot.yaml`, `paper-worker-verification.yaml`에 있다.
- **지갑:** DynamoDB `stock-automation-paper`의 키 `WALLET#CLOSING_BET#{session}`, `WALLET#DAY_TRADE`, `WALLET#MEDIUM_TERM`이다.
  - `_load_or_create_wallet`은 지갑이 **이미 있으면 `initial_cash`를 무시**하고 기존 잔액을 쓴다.
  - 그래서 환경변수만 바꾸면 20만 원으로 바뀌지 않는다.
- **손실 한도는 코드 상수다.**

| 전략 | 설정 | 지금 | 변경 |
|---|---|---|---|
| 종가배팅 | `StrategyConfig.max_daily_loss` | 10,000 | **3,300** |
| 종가배팅 조건부 (v0.5 브랜치) | `max_daily_loss × 0.5` | 5,000 | 1,650 (자동) |
| 단타 | `DayTradeConfig.maximum_position_loss` | 8,000 | **2,700** |
| 중기 | `MediumTermConfig.maximum_position_loss` | 20,000 | **6,700** |

## 변경 내용

### 1. 시작 금액 20만 원

- 위 CloudFormation 템플릿 4개의 시작 금액 파라미터 기본값을 `200000`으로 바꾼다.
- `aws_runtime.py`의 `os.getenv(..., "600000")` 기본값도 `"200000"`으로 바꾼다. `STARTING_CASH`를 쓰는 학습 튜닝 경로도 포함한다.

### 2. 새 지갑 (기존 원장 보존)

기존 지갑을 지우거나 덮어쓰지 않는다. 60만 원 원장과 20만 원 원장을 섞지 않는다.

- 환경변수 `PAPER_WALLET_EPOCH`를 추가한다. 비어 있지 않으면 모든 지갑 키 뒤에 `#<epoch>`를 붙인다.
  - 예: `WALLET#CLOSING_BET#KRX_1520#200K-20261103`
- 지갑 키를 만드는 함수를 하나 두고, 키를 쓰는 곳 전부가 그 함수를 쓰게 한다. 해당하는 곳:
  - 진입·청산·중기·단타
  - 대시보드 (`WALLET#` 접두사 읽기)
  - `tools/paper_operations.py`
- **청산은 진입 때 쓴 지갑에 돌려준다.** 포지션에 지갑 키를 저장하고, 청산은 그 키를 쓴다. 저장된 키가 없는 기존 포지션은 epoch 없는 옛 키로 청산한다.
- CloudFormation 템플릿에 `PaperWalletEpoch` 파라미터(기본값 빈 문자열)를 추가하고 컨테이너 환경변수로 넘긴다.
- 운영값은 `200K-20261103`으로 한다. 실제 스택 반영은 사용자가 승인한 뒤 한다.

### 3. 손실 한도 1/3

위 표대로 상수 3개를 바꾼다. 학습(`learning.py`)이 이 값을 조정하지 않는지 확인한다.

### 4. 적용 브랜치

- 11/03 운용은 main으로 돌므로 **main에 먼저** 커밋한다.
- 같은 변경을 `feature/closing-v0.4`(v0.5 구현 `c160fc6` 위)에도 cherry-pick한다.
- `rule_version`은 바꾸지 않는다. 원금과 한도만 바뀌고 종목 선택 규칙은 그대로다.

## 바꾸지 않는 것

- 배분 비율(종가 40%, 단타 25%, 중기 30%), 하드 필터, 점수식
- 실주문 관련 코드와 `LIVE_*` 환경변수. 실거래 한도는 실거래 준비 단계에서 따로 정한다.
- 기존 DynamoDB 항목. 삭제·수정하지 않는다.

## 테스트

1. epoch가 있으면 새 지갑이 200,000원으로 생성되고, 옛 지갑 항목은 그대로다.
2. epoch가 없으면 키가 지금과 같다 (하위 호환).
3. 새 지갑으로 진입한 포지션은 같은 지갑으로 청산된다. 저장된 키가 없는 옛 포지션은 옛 지갑으로 청산된다.
4. 원금 200,000원 종가배팅
   - 정식: 손실 ≤ 3,300원, 투자금 ≤ 80,000원
   - 조건부(브랜치): 손실 ≤ 1,650원, 투자금 ≤ 40,000원
5. 단타는 손실 ≤ 2,700원, 투자금 ≤ 50,000원이다. 중기는 손실 ≤ 6,700원, 투자금 ≤ 60,000원이다.
6. 대시보드와 `paper_operations.py`가 epoch 지갑을 읽는다.
7. CloudFormation 템플릿의 기본값 검사 테스트가 있으면 200000으로 맞춘다.

전체 회귀검증도 수행한다.

## 운영 반영 (사용자 승인 필요)

- 11/03 전에 이미지 빌드, 스택 파라미터 반영(`StartingCash` 등 200000, `PaperWalletEpoch=200K-20261103`), 배포를 해야 한다.
- AWS 비용·배포 변경이므로 사용자가 승인 범위를 따로 정한다.
- 반영 전 확인: 열린 모의 포지션이 없어야 한다. 있으면 그 포지션은 옛 지갑에서 청산이 끝난 뒤 전환한다.
