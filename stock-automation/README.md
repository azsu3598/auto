# Stock Automation MVP

한국 주식 종가배팅을 예약 실행하기 위한 **분석·모의매매 우선** 엔진이다. AWS
기본 배포는 키움 모의투자 키만 사용하며 실제 주문 권한이 없다. 별도의 수동
`live-*` CLI에는 실주문 API 호출 코드가 존재하지만 기본 비활성화 상태이고,
체결·부분체결 원장이 완성되기 전에는 운영용으로 활성화하지 않는다. 기본 전략은
KRX 15:20이며 NXT 19:55 전략은 별도 세션과 원장으로 명시적으로 실행할 때만
활성화된다.

## 구현 범위

- 거래대금·거래량·종가 강도·일봉·5분봉·VWAP·RSI·ATR·돌파 유지·호가 기반 후보 평가
- KRX 전략의 NXT 대상 종목 강제 제외
- 한 테마당 최대 한 종목 및 최종 0~3개 후보
- 최대 손실 10,000원과 최대 40% 배분을 동시에 지키는 수량 계산
- `IMMEDIATE` / `5M_CONFIRMED` 손절과 다음 거래일 09:10 청산 판단
- 동일 날짜·세션의 중복 모의체결 방지
- 0~100점으로 정규화된 후보 적합도와 검증 촉매 필수 필터
- 09:10 잔여수량 전량 청산 우선 및 1차 부분익절 1회 제한
- JSONL 원장, 기존 형식 CSV 이벤트 및 Markdown 보고서 출력
- 키움 REST API 응답을 정규화하는 스냅샷 빌더
- 종료된 거래의 실제 5분봉 경로 보관과 거래비용 포함 재생 백테스트
- 훈련/검증 시계열을 분리한 주간 챔피언-도전자 규칙 개선(모의전략 한정)
- 모의매수·부분익절·전량매도·손절 및 전략 승격 텔레그램 알림

## 로컬 실행

cd D:/Test/stock-automation

## 운영 대시보드

`SABU Trading Console`은 모의매매 원장을 읽기 전용으로 보여주는 PC·모바일 대응
운영 화면이다. 가용현금, 투자원금, 실현손익, 열린 포지션, 최근 실행 이력, 전략별
지갑, 일일 총자산 추이, 일일 예약표와 안전장치 상태를 한 화면에서 확인한다. 총자산
그래프는 `EQUITY#<PAPER|LIVE>#<날짜>` 스냅샷의 가용현금과 보유종목 평가금액을
합산한 확정값을 사용하며 모의·실거래 이력을 섞지 않는다. 스냅샷 저장 함수는 하루·
모드별 한 건만 조건부 기록하므로 같은 날 값을 조용히 덮어쓰지 않는다. 실제 평가를
위한 키움 현재가 수집과 AWS 예약 실행 연결은 PC-C 통합검증 단계에서 진행한다.
실거래 전환은 기존 잔고 보호와 체결 원장 대사가 완성되지 않았으므로 UI에서 강제로
잠겨 있다.

실거래 안전센터는 `CONTROL#LIVE`, `CONTROL#ACCOUNT_GUARD`, `LIVE_ORDER#` 레코드를
읽어 비상정지, 보호 기준선, 최근 10분 이내 대사 여부와 주문 진행 상태를 보여준다.
주문은 승인·전송·접수·체결/취소 단계로 표시하고 부분체결 수량과 미체결 잔량을
분리한다. `SUBMITTING`, `CANCEL_SUBMITTING`, `UNCERTAIN`은 정상으로 추정하지 않고
즉시 확인이 필요한 상태로 표시한다. 계좌번호·계좌 별칭·계좌 지문 원문은 API 응답과
화면에 포함하지 않는다. 모바일에서는 최근 실행 이력이 카드형으로 바뀌고 하단 빠른
메뉴로 안전센터·포지션·이력을 이동한다.

최근 실행 이력은 매수·매도·`NO_TRADE` 결과와 함께 당시 `reason_codes` 및 선택
후보의 근거를 한글 설명으로 표시한다. 예를 들어 거래대금·거래량 증가, 5분봉
20이평/VWAP 위치, 촉매 확인, 목표가 도달, 확인 손절, 예약 청산 이유를 최대 5개까지
보여준다. 기록에 없던 이유는 UI가 추정해서 만들지 않고 `기록 없음`으로 표시한다.

실행 모드는 단일 선택이 아니라 전략별 독립 선택으로 설계한다. 종가배팅·중기·단타마다
`모의`와 `실거래`를 각각 선택할 수 있어 두 항목을 동시에 켠 그림자 운용도 가능하다.
이 경우 모의 원장과 실거래 원장, 자금, 포지션, 성과는 절대 합치지 않는다. 현재 UI는
이 선택 구조와 저장 형식(`CONTROL#STRATEGY_MODE#<전략>`)만 표시하며 모든 변경
컨트롤이 잠겨 있다. Cognito 인증, 감사로그, 키움 통합검증이 끝나기 전에는 UI나
DynamoDB 값만으로 실거래가 활성화되지 않는다.

AWS 연결 전 샘플 데이터로 화면을 확인한다.

```bash
PYTHONPATH=src python3 -m stock_automation.cli dashboard \
  --fixture examples/dashboard_fixture.json
```

브라우저에서 `http://127.0.0.1:8765`를 연다. Windows PowerShell에서는 다음과 같다.

```powershell
$env:PYTHONPATH="src"
python -m stock_automation.cli dashboard --fixture examples/dashboard_fixture.json
```

배포 후 실제 모의 원장은 AWS CLI 인증이 된 환경에서 `PAPER_TABLE`을 지정해 읽는다.
안전센터까지 연결할 때는 읽기 전용 IAM 권한과 `LIVE_ORDER_TABLE`을 함께 지정한다.
두 테이블이 다르면 대시보드가 읽기 결과만 합치며 어떤 레코드도 수정하지 않는다.

```bash
PAPER_TABLE=<DynamoDB 테이블명> PYTHONPATH=src \
  python3 -m stock_automation.cli dashboard
```

현재 서버는 인증되지 않은 외부 노출을 막기 위해 `127.0.0.1`에만 바인딩한다. 인터넷과
휴대폰 외부망에서 접속하는 AWS 웹 콘솔은 Cognito 인증과 HTTPS를 붙인 뒤 별도
배포한다. 포트를 외부에 직접 개방하지 않는다.

배포 전 진단은 비밀값을 출력하지 않고 모의투자 모드, 주문 게이트, 키움·OpenDART
자격증명 존재 여부와 AWS 환경변수를 검사한다. `--online`을 추가하면 주문 없이
키움 종목목록과 OpenDART 법인코드 읽기만 시험한다.

```bash
stock-automation doctor --aws
stock-automation doctor --aws --online
```

## 입력 데이터 계약

`MarketSnapshot`은 반드시 시간대가 포함된 기준시각, 세션, 시장 등락률, 데이터
출처 및 종목별 `Quote`를 제공해야 한다. 종목에는 현재가·고저가·거래량·거래대금,
전일 거래량, 5/20/60/120일선, RSI(14), ATR(14), 5분 20이평과 기울기,
세션 VWAP, 마감 거래량 팽창, 고점·저점 상승 구조, 돌파 유지, 구조적 지지선과
NXT 여부가 필요하다. 뉴스·테마는 차트보다 낮은 비중의 보조 맥락이다. 지연
데이터이거나 지지선·분봉 이력이 불충분하면 프로그램은 해당 종목을 제외한다.

키움 어댑터는 다음 공식 API를 사용한다.

- `ka10099`: 종목정보 및 NXT 가능 여부
- `ka10032`: 거래대금 상위
- `ka10007`: 현재 시세와 호가
- `ka10081`: 일봉
- `ka10080`: 5분봉

촉매와 테마는 별도 뉴스/공시 수집기가 제공해야 한다. 키움 테마 강도는 후보의
맥락으로만 사용하며 검증 촉매로 인정하지 않는다. 날짜별 촉매 파일에서 뉴스·공시가
검증된 종목만 최종 점수 계산으로 진입한다.

종가배팅 점수는 종목이 속한 시장의 지수 변화를 함께 반영한다. 코스피 종목은
코스피, 코스닥 종목은 코스닥을 기준으로 -1% 아래부터 최대 10점을 점진적으로
감점하고 -3% 이하에서는 신규 진입 후보에서 제외한다. 시장 구분이 없는 구형
스냅샷은 두 지수 중 더 약한 값을 사용해 위험 필터를 우회하지 못하게 한다.

기관 수급은 키움 `ka90009`의 당일 기관 순매수·순매도 상위 자료만 사용하며 외국인
자료는 점수에 사용하지 않는다. 프로그램 수급은 `ka90004`의 종목별 순매수대금을
원 단위로 정규화해 반영한다. 확인된 양수일 때만 각각 1.5점을 가산하며, 종목이
상위 자료에 없거나 API 확인에 실패하면 값을 추정하지 않고 가점 없이 위험 표시에
남긴다.

키움 `ka10007`, `ka10032`, `ka10081`의 거래대금은 공식 응답 단위가 백만원이므로
어댑터에서 원 단위로 변환한 뒤 유동성 기준과 비교한다. 시가총액(`ka10001.mac`)과
손익 항목의 억원 단위도 중기 스냅샷에서 원으로 정규화한다.

## 1~2개월 보유 전략

`medium-analyze`는 종가배팅과 다른 입력·결정 ID·원장 파일을 사용하는 20~40
거래일 모의전략이다. 20·60·120일선 배열과 기울기, RSI, ATR, 20일 거래량,
20·60일 수익률, 지지·저항 및 손익비를 우선 평가하고 PER·PBR·ROE와 흑자는
안전 필터로 사용한다.

공시 검증이 없거나 감사·상장폐지·자본훼손·희석 이벤트가 있으면 차트 점수가
높아도 매수하지 않는다. 키움은 `ka10001`의 밸류에이션·손익 수치를 제공하지만
공시 위험은 OpenDART `corpCode.xml`과 `list.json`으로 자동 검증한다. 최대 30% 배분, 포지션 손실 2만원,
20거래일 재검토 및 40거래일 최대 보유기간을 종가배팅 계좌와 별도로 적용한다.

장 마감 분석 가격을 체결가로 소급하지 않는다. 15:40에는 신호와 진입 상한만
기록하고, 다음 거래일 09:15에 확인한 가격·공시를 다시 검사해 모의 진입하거나
취소한다. 열린 포지션은 매 거래일 15:35 확인가로 재평가하며 목표가, 투자 논리
훼손, 공시 위험 및 최대 보유기간에 따라 보유·부분익절·전량청산을 결정한다.

## 장중 단타 기본 엔진

`daytrade-analyze`는 종가배팅·중기전략과 모델, 점수, 자금, 포지션 ID 및 JSONL
원장을 공유하지 않는 세 번째 모의전략이다. 직접 만든 스냅샷뿐 아니라
`daytrade-kiwoom-scan`으로 키움 읽기 API에서 당일 데이터 한 번을 수집해 평가할 수
있다. AWS 상시감시나 실주문 경로는 연결하지 않았다.

- 신규 진입 스캔 허용 시간: KST 09:10~14:50
- 의무 당일 청산: KST 15:10
- NXT 가능 종목 제외, 최대 한 종목·자금 25%·계획손실 8천원
- 거래대금, 5분봉 거래량, 5분 20이평, VWAP, 돌파 유지 또는 이평 회복,
  당일 촉매, 기관·프로그램 수급 및 시장 약세를 별도 점수로 평가
- 5분봉 손절 확인과 별도 비상 하드 스톱 적용
- 기본 점수 65점 미만 또는 조건 불충족이면 `NO_TRADE`

입력 파일을 직접 준비한 기본 실행 예시는 다음과 같다.

```bash
stock-automation daytrade-analyze \
  --snapshot data/daytrade-snapshot.json \
  --ledger data/daytrade-ledger.jsonl \
  --cash 600000
```

키움 단발 스캔은 당일 출처와 검증시각이 기록된 촉매 파일을 요구한다. 촉매가 없는
종목은 애초에 키움 상세조회 대상에서 제외하며 명령은 주문 API를 호출하지 않는다.

```bash
stock-automation daytrade-kiwoom-scan \
  --catalysts config/catalysts/2026-10-12.json \
  --ledger runtime/daytrade-paper-ledger.jsonl \
  --cash 600000
```

대시보드는 `DAY_TRADE` 지갑·포지션과 `DAY#` 이벤트를 종가배팅·중기와 다른 전략으로
표시한다. DynamoDB 저장 계층은 `DAY#` 결정 이벤트, `OPEN#DAY_TRADE` 포지션 및
`WALLET#DAY_TRADE` 차감을 한 트랜잭션으로 처리하며 `NO_TRADE`도 별도 이벤트로 남긴다.
현재 단발 명령과 실제 AWS 테이블의 연결·키움 모의 통합검증은 PC-C에서 진행한다.

AWS에서는 `RUN_PHASE=DAY_TRADE_ON_DEMAND`로 명시적으로 시작한 ECS 작업만 단타
스냅샷과 결정을 S3·DynamoDB에 기록한다. 단타 스케줄은 CloudFormation에 만들지
않았으므로 자동 반복이나 상시 감시는 발생하지 않는다.

완전한 장중 단타는 이 단발 명령을 반복 호출하는 방식이 아니라 하나의 장중 세션이
연결·시세 최신성·후보 교체·진입·손절·익절·당일 청산을 계속 관리해야 한다. 향후
EC2 기반 연속 감시 구조와 비용은
[`연속_단타_AWS_운영설계_및_예상비용.md`](../docs/프로그램%20설계/연속_단타_AWS_운영설계_및_예상비용.md)에
정리되어 있다. 현재는 설계 문서만 있으며 실행 코드와 인프라는 구현되지 않았다.

세 전략의 운영 상태는 서로 독립적이다.

| 전략 | 실행 방식 | 기본 보유 | 전용 규칙 버전 |
|---|---|---|---|
| 종가배팅 | 15:20 분석 | 다음 거래일 09:10까지 | `closing-v0.2` |
| 중기 | 장 마감 신호·다음 날 확인 | 20~40거래일 | `medium-chart-v0.1` |

python -m stock_automation.cli medium-analyze ^

## 안전 경계

- AWS 기본 스택에는 실제 주문 권한과 실계좌 비밀값이 없다.
- API 오류·지연·스냅샷 세션 불일치 시 실패 종료한다.
- 모의 체결은 확인 시점의 최우선 매도호가 또는 현재가를 사용하며 과거 가격으로
  소급하지 않는다.
- KRX와 NXT 전략의 세션·원장·성과를 합치지 않는다.
- 기록 데이터로 개선된 규칙도 `PAPER_ONLY`가 아니면 로드하지 않는다.
- 학습 규칙은 안전 범위 안의 차트 임계값만 바꾸며 주문·자금·손실 한도를
  스스로 변경하지 못한다.
- AWS 배포 전 키움 모의투자 키, Secrets Manager, S3/DynamoDB 저장소와 거래일
  캘린더를 연결해야 한다.

수동 실주문 CLI는 코드에 포함돼 있지만 AWS 모의전략 결정과 자동 연결되어 있지
않다. 향후 실주문을 승인하더라도 기본값은 비활성화이며, 정확한 주문내용 해시와
5분 이내 사용자 승인, 최신 시세, 주문·총노출·일손실·보유종목 한도, 중복 주문
방지, 계좌 별칭 일치 및 비상정지 해제를 모두 통과해야만 승인 상태가 된다. 가격,
수량 또는 계좌가 바뀌면 기존 승인은 즉시 무효다. 주문번호 수신은 체결이 아니다.
`live-supervise`는 확인된 누적 체결분만 원장에 반영하고, 기본 180초가 지난 미체결
잔량을 키움 `kt10003`으로 한 번만 취소 요청하며, 계좌 잔고가 `보호 기준선 + 프로그램
포지션`과 정확히 다르면 비상정지를 켠다. 주문·취소 응답이 불명확한 경우에는 자동으로
재전송하지 않고 `UNCERTAIN` 상태와 비상정지로 종료한다.

기존 보유종목 보호를 위해 계좌번호 원문을 저장하지 않는 SHA-256 계좌 지문과 최초
보유수량 기준선을 한 번만 잠그는 `live-account-baseline` 골격도 포함돼 있다.
기준선은 비상정지가 켜진 상태에서만 만들 수 있고 이후 같은 테이블에서 덮어쓸 수
없다. 매도 허용수량은 `프로그램의 확인된 실제 체결수량`과 `전체 보유량에서 보호
기준선을 뺀 수량` 중 작은 값으로 제한된다. `live-reconcile`은 키움 주문번호를 다시
조회해 누적 체결수량의 증가분만 DynamoDB 프로그램 포지션에 원자적으로 반영한다.
부분체결·완전체결·취소·거부를 분리하며 같은 체결 조회를 반복해도 수량을 중복으로
더하지 않는다. 재시작 시 진행 중 주문을 다시 조회할 수 있고, `SUBMITTING`,
`CANCEL_SUBMITTING`, `UNCERTAIN`처럼 결과가 모호한 상태는 추측 복구하지 않고 비상정지한다.
주문번호가 조회되지 않거나 계좌 수량과 원장이 맞지 않아도 비상정지한다.

```bash
# 실계좌에서 미체결 취소까지 가능하므로 통합검증 전에는 실행하지 않는다.
python -m stock_automation.cli live-supervise \
  --account-alias main --max-unfilled-seconds 180 \
  --confirm SUPERVISE_REAL_ORDERS
```

이 명령은 한 번 실행하고 종료하며 상시 감시나 AWS 예약은 아직 연결하지 않았다.

기능 코드가 추가됐어도 키움 실제 환경과 AWS에서 통합 검증되지 않았으므로 실거래 UI
잠금은 유지한다. `LIVE_ORDER_ENABLED` 기본값도 비활성이고 비상정지가 기본 ON이다.

## AWS 예약 작업

`infra/cloudformation.yaml`은 다음 모의매매 작업을 만든다.

안전한 최초 배포를 위해 모든 핵심 예약은 `CoreScheduleState=DISABLED`가 기본값이다.
거래일 파일 업로드와 `doctor --aws --online` 읽기 전용 점검을 통과한 뒤에만
`ENABLED`로 스택을 갱신한다. NXT는 별도 `NxtScheduleState`를 명시적으로 켜야 한다.

- 14:50 KST: KRX 전체 후보 스캔 스냅샷
- 15:10 KST: 후보 재검증 스냅샷
- 15:20 KST: KRX 최종 `BUY` 또는 `NO_TRADE`
- 19:55 KST: NXT 최종 판단(기본 `DISABLED`)
- 다음 거래일 09:05 KST: 비상 손절·목표가 조기 점검
- 다음 거래일 09:10 KST: 남은 수량 모의청산
- 토요일 08:00 KST: 종료 거래를 이용한 주간 워크포워드 튜닝
- 15:40 KST: 별도 중기 전략 신호 생성(당일 체결 없음)
- 다음 거래일 09:15 KST: 중기 신호 가격·공시 재검증 후 모의 진입 또는 취소
- 15:35 KST: 열린 중기 포지션 종가 재평가 및 모의 매도 판단

결과와 원본 스냅샷은 S3, 멱등 모의체결과 열린 포지션은 DynamoDB 온디맨드에
저장한다. 같은 날짜·세션을 재실행해도 조건부 쓰기로 중복 포지션을 만들지 않는다.
KRX 종가배팅, NXT 종가배팅, 중기 전략은 각각 별도 `WALLET`을 사용한다. 매수 시
원금과 매수 수수료를 차감하고 매도 시 수수료·세금을 제외한 순매도대금을 더하므로,
다음 거래의 수량은 고정 초기금이 아닌 누적 가용현금으로 계산된다. 총비용과 순실현
손익도 매매 이벤트와 같은 DynamoDB 트랜잭션으로 갱신된다.

거래일 15:50에는 `EQUITY_SNAPSHOT_1550` 단기 ECS 작업이 각 모의전략 지갑의
가용현금과 열린 포지션의 검증 현재가 평가액을 합산해 일일 총자산을 저장한다.
현재가가 누락되거나 오래됐으면 해당 날짜 값을 만들지 않는다. 이 예약도 최초 배포
시 `CoreScheduleState=DISABLED`이며 PC-C 모의 통합검증 후에만 활성화한다.
키움 키는 Secrets Manager의 `app_key_mock`, `app_secret_mock` 필드에서 ECS 비밀
환경변수로 주입하며, Task Role에는 주식 주문 권한이 없다.

모의매수·부분익절·전량매도·손절이 원장에 처음 기록되면 휴대폰 텔레그램으로
알림을 보낸다. 텔레그램 Bot API 자체에는 발송 비용이 없고 별도의 상시 실행
프로세스도 필요하지 않다. 재시도나 중복 예약 실행은 조건부 원장 쓰기로 같은
모의체결을 다시 만들지 않는다. 매매 이벤트와 알림 outbox를 하나의 DynamoDB
트랜잭션으로 저장하므로 메신저 장애가 나도 알림을 `PENDING`으로 남겨 동일 예약
작업의 재시도에서 다시 전송한다. 외부 메신저 응답 직후 작업이 중단되는 극히 드문 경우에는 중복 알림이
가능하므로 메시지의 이벤트 ID를 기준으로 구분한다. 실제 주문을 도입할 때는 주문 접수와 체결 확인을
별도 이벤트로 나누고, **키움 체결 확인이 끝난 뒤에만** 사용자 알림을 보내도록
연결한다. 현재 알림에는 `모의매매`가 명시된다.

### 텔레그램 알림 준비

1. 텔레그램 `@BotFather`에서 `/newbot`으로 봇을 만든다.
2. 생성한 봇과의 대화에서 `/start`를 한 번 보낸다.
3. Bot API `getUpdates` 결과의 `message.chat.id`를 확인한다.
4. Secrets Manager JSON에 `bot_token`, `chat_id`를 저장한다.
5. 배포 파라미터 `NotificationChannel=telegram`과
   `NotificationSecretArn=<해당 Secret ARN>`을 전달한다.

봇 토큰은 비밀번호처럼 취급하며 코드·로그·S3에 기록하지 않는다. 알림용 JSON은
기존 키움 Secret에 필드를 추가해 같은 ARN을 전달해도 되므로 별도 Secret이
필수는 아니다. 카카오 `나에게 보내기` 어댑터도 선택 가능하지만 OAuth 갱신과 앱
설정이 더 복잡하므로 기본값은 텔레그램이다. 기존 이메일 기능도 삭제하지 않았다.
`NotificationChannel=email`과 `NotificationEmail`을 지정하면 SNS 구독 확인 후
이메일로 동일한 알림을 받을 수 있다.

## 기록 기반 자동 개선

전량 청산된 포지션은 진입 당시 스냅샷과 이후 실제 5분봉을
`replay-cases/<session>/`에 보관한다. 주간 작업은 시간순으로 앞 70%를 훈련,
뒤 30%를 검증에 사용하고 기존 챔피언보다 검증 성과가 나은 도전자만 승격한다.
최소 40건, 최소 검증 거래 5건, 순이익 양수, 최대낙폭 제한을 모두 통과해야 한다.

자동 조정 대상은 다음 다섯 가지뿐이다.

- 최소 차트 점수
- 최소 종가 강도
- 최소 거래량 팽창률
- 허용 일간 상승률 상한
- 5일선 최대 이격도

승격된 설정은 `config/rules/<session>.json`에 `PAPER_ONLY`로 저장된다. KRX와
NXT는 별도로 학습한다. 실제 주문 모드로 자동 전환하거나 실거래 규칙을 자동
교체하는 경로는 없다.

배포 전 거래일 파일은 반드시 넣고, 검증된 뉴스 촉매가 있을 때 촉매 파일을 추가한다.

```text
config/calendar/current.json
config/catalysts/YYYY-MM-DD.json  # 선택
config/dart/corp-code-map.json  # 프로그램이 자동 생성·주 1회 갱신
config/disclosures/YYYY-MM-DD.json  # 프로그램이 자동 생성
```

거래일 파일 예시는 `{"year": 2026, "holidays": ["2026-10-09"]}` 형식이다.
촉매 파일은 종목코드를 키로 하고 `theme`, `summary`, `score`, `verified`,
`source`, 시간대가 포함된 `verified_at`을 제공한다. `verified: true`, 비어 있지
않은 출처, 실행일과 같은 KST 날짜의 검증시각이 모두 있어야 검증 촉매로 인정한다.
예시는 `{"123456":{"theme":"로봇","summary":"수주 공시","score":0.8,
"verified":true,"source":"OpenDART: 20261008000123","verified_at":
"2026-10-08T14:55:00+09:00"}}`이다. 파일이 없거나 조건을 만족하지 못하면 키움
`ka90001`·`ka90002`의 당일 테마 상승률과 상승/하락 종목 폭을 보조
맥락으로만 사용하며 신규 진입은 하지 않는다. 파일에 검증된 뉴스·공시가 있으면
같은 종목의 테마 맥락을 덮어쓰고 최종 평가를 허용한다. 어느 경우에도 뉴스·테마
점수는 차트 점수보다 큰 비중을 갖지 않는다.
중기 공시 파일은 OpenDART 조회 결과를 종목코드별 `checked_at`, `risk_flags`,
`catalyst`, 근거 공시 목록으로 저장한 캐시다. API 키 오류·호출 제한·불완전한
페이지·최신 검증시각 누락이 발생하면 신규 진입은 자동 취소되며, 보유 포지션의
종가 재평가는 검증을 복구할 때까지 실패 종료해 임의 매도를 만들지 않는다.

CloudFormation 배포 시 컨테이너 이미지 URI, 서브넷, 보안 그룹, 키움 모의투자
Secrets Manager ARN, 무료 OpenDART 키의 `DartSecretArn`과 실제 적용 수수료·세금(`BuyFeeBps`, `SellFeeBps`,
`SellTaxBps`)을 파라미터로 전달한다. 텔레그램 알림용
`NotificationSecretArn`도 전달한다. 이메일을 선택하면 대신 `NotificationEmail`을
전달한다. 비용률은 계좌와 시점에 따라 달라질 수 있어 코드에 고정값을 넣지 않았다.
NXT 예약은 KRX 전략과 성과를 섞지 않기 위해 별도 스케줄이며 기본적으로 꺼져 있다.
